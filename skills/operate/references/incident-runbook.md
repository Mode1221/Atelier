# 장애 대응 런북 (템플릿)

`docs/runbook.md` 로 복사해 **프로젝트의 실제 명령어**로 채운다.

## 0. 연락처·접근
- 호스팅·DB·도메인·스토어·PG 콘솔 주소 (비밀번호는 비밀번호 관리자에만)
- 2단계 인증 복구 코드 보관 위치

## 1. 판단 (5분)
1. 영향 범위: 전체 / 일부 기능 / 일부 사용자
2. 최근 변경: 마지막 배포·설정 변경·외부 서비스 공지
3. 등급
   - **치명**: 전체 불가, 데이터 손실·유출 가능성, 결제 오류 → 즉시 대응
   - **높음**: 핵심 기능 불가 → 1시간 내
   - **보통**: 우회 가능 → 다음 업무일

## 2. 완화 (고치기 전에 멈추기)
| 상황 | 조치 | 명령/방법 |
|---|---|---|
| 배포 직후 문제 | 롤백 | `<프로젝트 롤백 명령>` |
| 특정 기능 문제 | 기능 플래그 끄기 | `<방법>` |
| 과부하 | 한도 강화·캐시·스케일 업·점검 모드 | `<방법>` |
| 외부 서비스 장애 | 폴백 강제 켜기 | `<방법>` |
| 비용 폭주 | 해당 기능 끄기, API 키 일시 중지 | `<방법>` |
| 키 유출 | 즉시 폐기·재발급·배포 | `<방법>` |
| 데이터 손상 | 쓰기 중지(점검 모드) → 백업 복구 | `backup-recovery.md` |

## 3. 공지
- 상태 공지 위치: 앱 배너 / 상태 페이지 / SNS
- 템플릿: "현재 [기능]에 문제가 있어 확인 중입니다. [시각]까지 업데이트하겠습니다."
- 복구 후: 원인 요약·영향·재발 방지 한 줄

## 4. 개인정보 유출 의심 시
- 즉시 차단·증거 보존(로그)
- 법정 통지·신고 의무와 기한 확인 (개인정보보호위원회 안내) — 기한이 짧으므로 가장 먼저 확인
- 전문가 상담

## 5. 사후 분석 (48시간 내)
`docs/incidents/YYYY-MM-DD-<요약>.md`
```markdown
- 발생·인지·완화·해결 시각
- 영향 (사용자 수, 기간, 데이터)
- 원인 (근본 원인까지 "왜"를 5번)
- 잘된 것 / 안된 것
- 재발 방지 조치 (담당·기한) → 테스트·알림·런북에 반영
```
비난 없는 기록. 목적은 재발 방지.
