# 모니터링·알림

## 알림 대상 (최소 세트)
| 대상 | 도구 예 | 알림 조건 (예) | 긴급도 |
|---|---|---|---|
| 업타임 | UptimeRobot, Better Stack, Cloudflare | `/health` 2회 연속 실패 | 즉시 |
| 에러 | Sentry | 새 오류 유형, 에러율 급증 | 즉시(급증) / 일일 요약(신규) |
| 응답 시간 | APM·호스팅 대시보드 | p95 가 목표의 2배 10분 지속 | 업무 시간 |
| 비용 | 클라우드 예산 알림, API 콘솔 | 월 예산 50%·80%·100% | 즉시(100%) |
| 외부 API 한도 | 자체 카운터 | 일 한도 80% | 업무 시간 |
| 인증서·도메인 | 모니터링 서비스 | 만료 14일 전 | 업무 시간 |
| 백업 | 크론 결과 | 실패 1회 | 업무 시간 |
| 비즈니스 | 분석 도구 | 가입·결제가 평소의 0 에 가까움 (조용한 장애) | 업무 시간 |

## 받는 곳
- 즉시: 휴대폰 푸시 (앱 알림 또는 메신저 웹훅)
- 업무 시간: 이메일·채널 요약

## 원칙
- 행동이 필요한 알림만. "보고만 하는" 알림은 일일 요약으로
- 알림마다 "받으면 무엇을 하나"를 런북에 연결
- 조용한 장애(오류 없이 기능이 안 됨)는 **비즈니스 지표 급감**으로 잡는다
- 외부에서 합성 모니터링: 핵심 흐름을 주기적으로 자동 실행 (E2E 를 운영에 가볍게)
