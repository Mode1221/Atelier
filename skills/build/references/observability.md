# 계측 (관측 가능성)

운영 중 "무슨 일이 일어나는지" 모르면 고칠 수 없다.

## 1. 에러 모니터링
- Sentry 등 연결: 프론트·백엔드·앱 모두
- 릴리스 버전 태그, 소스맵 업로드 (스택트레이스 읽을 수 있게)
- 개인정보(이메일·토큰·요청 본문) 자동 수집 끄기·마스킹
- 테스트 에러 1건 발생시켜 수신 확인

## 2. 로그
- 구조화 로그(JSON): 시각, 수준, 요청 ID, 사용자 ID(해시 또는 내부 ID), 이벤트, 소요 시간
- 요청 ID 를 프론트 → 백엔드 → 외부 호출까지 전달
- 비밀값·개인정보·토큰은 로그에 남기지 않는다
- 보관 기간 정하기

## 3. 헬스체크
- `/health`: 앱 살아 있음 / DB 연결 / 필수 외부 서비스 상태
- 외부 업타임 감시 서비스가 이 URL 을 주기적으로 호출 (operate O1)

## 4. 분석 이벤트
- spec S6 의 이벤트를 구현하고 대시보드에서 수신 확인
- 스테이징·운영 데이터 분리

## 5. 비즈니스 지표
- 가입 수, 활성 사용자, 결제, 외부 API 호출 수(비용)를 하루 단위로 볼 수 있게

## 점검
- [ ] 운영에서 오류가 나면 5분 안에 알 수 있다
- [ ] 사용자가 "안 돼요" 하면 요청 ID·시각으로 로그를 찾을 수 있다
- [ ] 외부 API 비용이 오늘 얼마인지 알 수 있다
