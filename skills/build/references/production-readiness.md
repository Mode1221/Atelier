# 운영 준비 체크리스트 (build 게이트)

**필수**를 전부 통과해야 build 단계를 끝낸다. 해당 없으면 `N/A (이유)`.
🚀 = **배포한 뒤에만 확인할 수 있는 항목**. 배포 전(로컬로 진행 중)에는 나머지 필수가 모두 통과하면 build 게이트는 `보류(배포 후 🚀 확인)` — 정상 진행이다. 🚀 항목은 첫 배포(`npm run deploy:first`) 직후 같은 표로 다시 본다.

## 기능
- [ ] **필수** Must 기능 수용 기준 전부 통과 (E2E)
- [ ] **필수** 상태별 화면(빈·로딩·오류·권한 없음·한도 초과) 구현
- [ ] **필수** 화면 테스트가 주요 화면에서 `null`·`undefined`·`NaN`·`[object Object]` 노출 0건 (`testing-strategy.md` 화면 텍스트 검사)
- [ ] **필수** 실제 브라우저 캡처로 핵심 화면을 한 번 이상 봤다. 못 봤으면 통과가 아니라 `— 사람 대기 (화면 확인)` 으로 남긴다
- [ ] **필수** 외부 서비스 장애 시 폴백 동작 확인
- [ ] 기능 플래그·점검 모드

## 서버 없는 앱 (기기 안에만 저장 — 모바일 로컬 앱·확장 등, 해당 없으면 N/A)
서버가 없으면 아래 필수 항목은 이렇게 바꿔 읽는다(PROJECT.md 에 `N/A (서버 없음 — 대신 …)` 로 적는다).
- 마이그레이션·백업 → **저장 형식 버전**(`schemaVersion`)과 옛 데이터 읽기 테스트, 내보내기·가져오기(기기 바꿀 때)
- 헬스체크·서비스 죽음 알림 → **충돌 보고**(Expo/Sentry 무료 등급)와 스토어 콘솔의 비정상 종료율
- 운영 지표 화면 → 스토어 콘솔(설치·활성 기기)과 앱 안 분석 이벤트(S6) — 본부 `stats.url` 은 수집용 작은 서버가 생길 때
- 스테이징·운영 분리·롤백 → 스토어 **내부 테스트 트랙**(TestFlight·Play 내부 테스트) → 단계적 출시, 문제 시 이전 빌드로 출시 중지
- 배포 없는 로컬 게이트: `npx expo export`(또는 스택의 로컬 빌드)가 통과하고 웹·시뮬레이터 화면으로 E2E·usertest 가 돌면 통과, 실제 폰·스토어 빌드는 `— 사람 대기`

## 공유 링크·여럿이 함께 고치는 서비스 (해당 없으면 N/A)
가입 없이 "링크를 가진 사람은 누구나 고친다" 같은 구조는 사람이 늘면 실수·장난이 생긴다. 크게 알리기(launch L5) 전에 필수.
- [ ] **필수** 되돌리기: 지우기는 표시만(soft delete) + 되살리기 기간, 또는 실행 취소
- [ ] **필수** 변경 기록: 누가·무엇을·언제 (목록 안에서만 보이게)
- [ ] **필수** 입력한 값은 전부 고칠 수 있다 (지우고 다시 넣게 하지 않는다)
- [ ] **필수** 다른 사람의 변경이 새로고침 없이 보인다 (무료 등급이면 짧은 간격의 "바뀌었나" 확인 + 입력 중이면 알림만)
- [ ] **필수** 동시에 같은 것을 바꿀 때 한 명만 성공하고 나머지에 이유를 알려 준다 (조건부 UPDATE·버전)
- [ ] 지운 것을 포함한 개수 한도 (지우고 넣기 도배 방지)
예: `examples/chaenggim-pyo` (F8~F10, `migrations/0004_activity_undo.sql`)
