# Build — 구현

목표: 명세의 Must 기능을 **동작하고, 테스트되고, 관측 가능하고, 되돌릴 수 있는** 상태로 운영 환경에 올린다.

> **빠른 길(기본)**: B1 · B2 · B4 · B8 · B9(에러 수신·S6 이벤트) · B10 · B12 · B13 · B14 (+ 계정이면 B3, 과금이면 B5). B6·B7·B11·B15 는 나중. 작업 중에는 바뀐 범위만 테스트하고 전체 검사는 게이트에서 한 번. 진행 규칙은 `../pilot/references/fast-path.md` 2절(단계 단위로 한 번에, 짧은 문서, 참고 문서는 필요한 절만). PROJECT.md 가 `꼼꼼한 길`이면 아래 전부.

"내 컴퓨터에서 된다"는 완료가 아니다. 완료 기준은 `references/production-readiness.md` 다.

## 입력
- `docs/spec.md`, `docs/architecture.md` (스토리·정책·데이터 모델·외부 연동·비기능 요구·작업 목록)
- `docs/design.md` + 토큰·시안

## 공통 루프 (모든 세부 단계)
1. 이번 작업의 완료 조건을 한 줄로 적는다 (spec 수용 기준 인용).
2. 구현 → 테스트 → 로컬 검증(린트·타입체크·테스트) → `/code-review` → 반영.
3. 작은 단위 커밋 (Conventional Commits). PROJECT.md 체크박스 갱신.
4. 명세와 달라진 점은 `docs/spec.md` 도 같이 고친다.

## 세부 단계

### B1. 기반
- 스택 확정: `references/free-tier.md` → `references/stack-templates.md`. 기준 = **무료 등급으로 운영 가능 > 사용자가 아는 것 > 운영 부담 적은 것 > 유행.**
- 유료가 필요한 선택은 실행 전에 금액·무료 대안을 보여 주고 결정을 받는다.
- 공식 생성 도구로 스캐폴딩. 린터·포매터·타입체크·테스트 러너 설정.
- **환경 분리**: 개발(local) / 스테이징(미리보기) / 운영. 무료·1인 서비스는 스테이징 서버를 따로 두지 않고 **미리보기 배포**(Workers `versions upload`·Pages 미리보기 주소 등)로 대신해도 된다 — 운영 DB 를 쓰지 않는 것만 지킨다. 환경마다 DB·키 분리. 운영 데이터로 개발하지 않는다.
- 시크릿: `.env.example`(이름만), 실제 값은 플랫폼 시크릿. `.gitignore` 확인.
- CI: 푸시마다 린트·타입체크·테스트·빌드 (`references/ci-deploy.md`).
- **검사 도구 설치**: `node <atelier>/skills/pilot/scripts/install-tools.mjs` → 프로젝트 `scripts/atelier/` 에 품질 게이트·사용성 테스트 실행기 복사 + `npm run quality`. CI 에 "품질 게이트" 단계를 테스트보다 먼저 넣는다.
- **종류별 첫 실행**: `references/stack-templates.md` 첫 표 (웹·로그인 웹·웹 게임·모바일 앱). **첫 배포 스크립트**(Cloudflare 스택): `templates/deploy-first.mjs` → 프로젝트 `scripts/deploy-first.mjs`, package.json `"deploy:first": "node scripts/deploy-first.mjs"`. 로그인 확인 → D1 생성(있으면 재사용) → `wrangler.toml` 에 database_id 기록 → 원격 마이그레이션 → 배포 → 비밀값 → 주소 출력까지 한 번에, 다시 실행해도 안전. 비밀값은 `.dev.vars.example` 에 이름만(`FEEDBACK_TOKEN=auto` 처럼 `auto` 면 자동 생성, 빈 값이면 배포 때 붙여 넣기) — 사람에게 `wrangler secret` 을 가르치지 않는다.
- 프로젝트 `CLAUDE.md`: 스택, 명령, 폴더 구조, 규칙(어댑터 경유 등, "유료 API 를 부르는 일괄 스크립트는 예상 비용을 먼저 보여 주고 승인 후 실행" — `../operate/references/cost-maintenance.md` 1-1).

### B2. 데이터 계층
- spec S3 의 데이터 모델을 **마이그레이션 파일**로 만든다. 운영 DB 는 마이그레이션으로만 바꾼다.
- 출시 뒤 바꿀 때는 **확장 → 이전 → 축소**: 추가만 하는 배포 → 코드 전환·데이터 옮기기 → 다음 배포에서 옛 것 삭제. `scripts/migration-check.mjs` 가 삭제·이름 바꾸기·기본값 없는 필수 칸·조건 없는 삭제를 막는다.
- 행 단위 권한(RLS)·외래키·인덱스·제약 조건.
- 시드 데이터(개발용)와 운영 데이터 분리.

### B3. 신원·권한
spec 의 신원 모델을 구현한다.
- 계정: `references/auth-accounts.md` — 가입·로그인·로그아웃·재설정·**탈퇴**·세션 만료까지 한 세트. 소셜 로그인을 넣으면 그날 바로 PROJECT.md "사람 할 일"에 "○○ 로그인 검수 제출(출시 2주 전까지)"를 올린다(`../guard/references/platform-review-kr.md`) — 코드보다 심사가 늦게 끝난다.
- 계정 없음(비밀 링크·토큰): 충분히 긴 무작위 값(128비트 이상), **해시로만 저장**, 상수 시간 비교, URL 조각(`#`)이나 헤더로 전달(서버 로그·Referer 에 남지 않게), 실패 속도 제한, 삭제 경로.

### B4. 핵심 기능 (수직 슬라이스)
- spec S7 순서대로 한 슬라이스씩: 화면 → API → DB → 테스트.
- 정책(S2)의 권한·상태·예외·한도를 **서버에서** 구현한다. 클라이언트 검사는 편의용일 뿐.
- 외부 API 는 어댑터 경유, 캐시, 사용자별 한도, 키 없을 때 폴백.
- 긴 작업은 비동기(큐·백그라운드 작업) + 진행 상태 표시.
- **생성형 AI 기능**(LLM 이 만든 글·이미지·추천을 보여 줌)이면 같은 슬라이스에서: 기능 화면에 "AI 가 만든 결과" 사전 고지 한 줄, 결과물에 AI 표시(보이는 배지, 공유되는 이미지면 보이는 표시 + 메타데이터). 문구·기준은 `../guard/references/privacy-checklist-kr.md` "인공지능 기본법". E2E 로 표시가 보이는지 확인한다.

### B5. 결제 (과금 있을 때)
`references/payments.md` 를 따른다. 결제는 직접 만들지 않는다 — 국내 웹은 **`templates/pay/` 를 설치**(`pay-first.mjs install`)하고 plans.js·약관(`../guard/templates/paid-terms-kr.md`)만 채운다. 완료: 테스트 키로 단건 결제·환불, 정기결제 등록·해지가 화면에서 한 번씩 된다.

### B6. 알림
- 이메일: 트랜잭션 메일(가입 확인·재설정·영수증)은 전용 서비스, 발신 도메인 인증(SPF·DKIM·DMARC).
- 푸시: 권한 요청은 가치를 보여 준 뒤. 알림 설정 화면에서 끌 수 있게.
- 광고성 알림은 수신 동의자만 (guard).

### B7. 관리자 도구
운영하려면 반드시 필요하다. 최소:
- 사용자 조회·정지·삭제, 콘텐츠 숨김(신고 처리), 결제·환불 조회
- 기능 플래그·점검 모드 켜기/끄기
- 관리자 행동 기록(감사 로그). 관리자 권한은 별도 인증
- 처음엔 DB 콘솔 + 스크립트여도 되지만 **절차는 문서화**한다.

### B8. 오류 처리·폴백
- design 의 상태별 화면(`screen-states.md`)을 전부 구현한다.
- 재시도(지수 백오프), 타임아웃, 중복 요청 방지(멱등 키), 동시 수정 충돌 처리.
- 외부 서비스 장애 시 폴백 동작을 실제로 꺼 보고 확인한다.

### B9. 계측
`references/observability.md` 를 따른다: 에러 모니터링, 구조화 로그, 분석 이벤트(spec S6), 헬스체크.
**운영 통계**: `references/ops-stats.md` — 종류별(웹: 하루 방문자, 앱: 활성 사용자, 저장소: GitHub 방문자) 숫자를 공통 형식의 공개 통계 주소로 내보내 본부 "운영 지표"에 매일 그린다. 출시 전에 넣는다(launch L5 "방문 측정 확인").

### B10. 테스트
`references/testing-strategy.md` 를 따른다. spec 수용 기준 = E2E 시나리오.
**품질 게이트** (B1 에서 설치한 `scripts/atelier/quality-gate.mjs`, `npm run quality`) 를 CI 에 넣는다 — 증거 검사·요구사항 추적·분석 이벤트 계획·DB 변경 안전·비밀값 유출을 매 push 마다 자동으로.

### B11. 성능·SEO·다국어
`references/web-quality.md` 를 따른다. spec S5 비기능 요구 숫자를 측정해서 확인.

### B12. 배포 파이프라인
- 스테이징(미리보기) 배포 → 확인 → 운영 배포. 운영 배포 후 스모크 테스트 자동 실행.
- 무료 스택 기본: **첫 배포는 `npm run deploy:first` 한 줄**(B1). 사람 몫은 "Cloudflare 가입 + 이 명령 한 줄"뿐이고, PROJECT.md "사람 할 일"에도 그 한 줄만 적는다. 이후 자동 배포는 GitHub Actions + `wrangler deploy` (`references/ci-deploy.md`, 선택).
- **롤백 방법**을 실제로 한 번 해 본다. DB 마이그레이션은 되돌릴 수 있게 쓰거나 전진 수정 절차를 둔다.
- 모바일: 스토어 빌드·서명 키 백업, 내부 테스트 트랙. 앱 버전·빌드 번호 규칙.
- 기능 플래그로 "배포"와 "공개"를 분리하면 위험이 줄어든다.

### B13. 운영 준비 체크리스트
게이트 판정 전에 PROJECT.md "디자인 도구 계획"의 **build 게이트 전** 칸만 실행한다(예: 도구형 `/impeccable harden`, 없으면 대체). 칸이 비어 있으면 디자인 스킬을 쓰지 않는다.
`references/production-readiness.md` 의 필수 항목을 전부 확인하고 결과를 `docs/build.md` 에 남긴다. 이게 build 게이트다.
계정·결제가 필요해 AI 가 못 하는 항목은 `⏳ 사람 대기` 로 표시하고 PROJECT.md "사람 할 일"로 옮긴다 → 게이트 판정 **보류**.
성능은 `references/bench.js` 를 프로젝트에 맞게 고쳐 측정한다.

### B14. 서비스 지도
`templates/service-map.md` 를 `docs/service-map.md` 로 복사해 **실제 값으로** 채운다. 대표가 "코드가 어디 있어?", "지표는 어디서 봐?", "계정이 뭐가 있지?"를 물었을 때 이 한 장으로 답한다.
- 코드 위치·서비스가 도는 곳·주소·DB, **계정 목록**(서비스·가입 이메일·2단계 인증·결제 수단 — 비밀번호는 적지 않음), 비밀값 **이름과 보관 위치**(값은 적지 않음), 자동으로 도는 것(크론·워크플로), 지표·장애 알림을 보는 곳, 월 비용, 컴퓨터를 잃어버렸을 때 되살리는 법.
- 배포·계정·알림이 바뀔 때마다 같이 고친다. operate·company 는 이 파일을 먼저 읽는다.

### B15. 자체 도메인 (선택, 사람 결정)
무료 주소(`*.workers.dev` 등)로 시작해도 된다. 사기로 하면 `references/domain.md` 순서대로: 구매 → DNS 연결 → 서비스에 붙이기 → 옛 주소 넘겨주기(301) → 공유 링크·OG·약관·로그인 콜백 주소 바꾸기 → 검색 등록 갱신 → 갱신일을 만료 목록에. 이미 알린 주소는 끊지 않는다.
