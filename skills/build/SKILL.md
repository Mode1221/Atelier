# Build — 구현

목표: MVP Must 기능을 **동작하고, 테스트되고, 배포된** 상태로 만든다.

## 입력
- `docs/idea.md` (MVP 범위), `docs/design.md` + 토큰 파일
- PROJECT.md 의 스택·경험 수준

## 절차

### 1. 스택 확정
- `references/stack-templates.md` 에서 프로젝트 형태에 맞는 조합을 제안한다.
- 기준 순서: **사용자가 이미 아는 것 > 운영 부담이 적은 것 > 유행하는 것.**
- 결정과 이유를 PROJECT.md "결정 기록"에 남긴다.

### 2. 스캐폴딩
- 공식 생성 도구로 프로젝트를 만든다(`create-next-app`, `create-expo-app`, `flutter create`, Godot 새 프로젝트 등).
- 바로 추가: 린터·포매터, 타입체크, 테스트 러너, `.env.example`, `.gitignore`(비밀값·빌드 산출물).
- 프로젝트 루트에 `CLAUDE.md` 를 만든다: 스택, 실행·테스트 명령, 폴더 구조, 규칙.
- 디자인 토큰 파일을 프로젝트에 연결한다.

### 3. 기능 구현 (Must 하나씩)
기능마다 이 루프를 돈다:
1. 완료 조건을 한 줄로 적는다.
2. 구현한다. 작은 단위로 커밋(Conventional Commits).
3. 테스트를 쓴다: 핵심 로직은 단위 테스트, 핵심 흐름 1개는 E2E.
4. 로컬 검증(린트·타입체크·테스트)을 통과시킨다.
5. `/code-review` 로 검토하고 지적을 반영한다.
6. PROJECT.md 체크박스를 갱신한다.

### 4. CI
- 푸시·PR 마다 린트·타입체크·테스트·빌드를 돈다. `references/ci-deploy.md` 참고.

### 5. 배포
- 형태별 배포 대상은 `references/ci-deploy.md` 참고.
- 비밀값은 환경변수·플랫폼 시크릿에만 둔다. 저장소에 커밋하지 않는다.
- 운영 필수 3종: **에러 모니터링**, **기본 분석**(핵심 지표 1~2개), **백업**(DB 가 있다면).

## 산출물
- 동작하는 코드, 테스트, CI 설정, 배포 URL 또는 빌드 파일
- `CLAUDE.md`, `README.md`(실행 방법)

## 완료 조건
- [ ] Must 기능 전부 동작
- [ ] 핵심 흐름 E2E 테스트 1개 이상 통과
- [ ] CI 녹색
- [ ] 배포 URL / 테스트 빌드 존재
- [ ] 에러 모니터링·분석 연결
- [ ] 비밀값이 저장소에 없음 (`git log -p | grep -i "key\|secret\|token"` 등으로 확인)

## 원칙
- 범위 밖 기능이 떠오르면 만들지 말고 PROJECT.md 의 Should/Could 로 보낸다.
- 외부 API 는 어댑터 한 곳을 거쳐 호출한다(나중에 교체·모킹이 쉽다).
- 키가 없어도 앱이 죽지 않게 폴백을 둔다.
- 결제·인증은 직접 만들지 말고 검증된 서비스를 쓴다.
