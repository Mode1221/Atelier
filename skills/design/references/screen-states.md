# 상태별 화면

화면마다 아래 상태를 표로 정의한다. 해당 없으면 "해당 없음"이라고 쓴다.

| 상태 | 언제 | 보여 줄 것 |
|---|---|---|
| 첫 사용 (빈 상태) | 데이터가 아직 없음 | 무엇을 하면 되는지 + 행동 버튼 1개. 예시·샘플 데이터 |
| 결과 없음 | 검색·필터 결과 0 | 조건 완화 제안 |
| 로딩 | 데이터 가져오는 중 | 스켈레톤(레이아웃 유지). 1초 미만이면 표시 생략 |
| 부분 로딩 | 일부만 도착 | 도착한 것부터 표시 |
| 오류 (재시도 가능) | 네트워크·서버 오류 | 원인 한 줄 + 재시도 버튼. 입력값 유지 |
| 오류 (복구 불가) | 삭제됨·잘못된 링크 | 홈으로 가기 |
| 권한 없음 | 로그인 필요·남의 데이터 | 로그인 유도 또는 접근 요청 |
| 한도 초과 | 무료 사용량 소진 | 남은 시간·업그레이드 안내 |
| 오프라인 | 연결 끊김 | 오프라인 배너, 가능한 기능 유지 |
| 긴 콘텐츠 | 긴 이름·많은 항목 | 말줄임·페이지네이션·가상 스크롤 |
| 저장 중 / 완료 | 폼 제출 | 버튼 로딩 → 토스트. 중복 제출 방지 |
| 점검 중 | 서비스 점검 | 점검 안내·예상 종료 시각 |
| 강제 업데이트 (앱) | 최소 버전 미만 | 업데이트 버튼 |

## 문구 원칙
- 오류: "무엇이 잘못됐는지 + 어떻게 하면 되는지". 기술 용어·오류 코드만 보여 주지 않는다.
- 사용자 탓하지 않기 ("잘못 입력하셨습니다" ✗ → "이메일 형식을 확인해 주세요" ○)
