# 출시 준비 점검 (Go / No-Go)

출시 전날 확인. **No-Go** 항목이 하나라도 실패하면 출시를 미룬다.

## No-Go (필수)
- [ ] guard 완료 조건 전부 통과
- [ ] build 운영 준비 체크리스트 필수 항목 통과
- [ ] 운영 환경에서 핵심 흐름(가입 → 핵심 행동 → 결제) 직접 1회 성공
- [ ] 장애가 나면 사람이 안다 — 휴대폰 알림 또는 매시간 점검 → 메일(이슈) (operate O1)
- [ ] 운영자가 지표를 볼 곳이 있다 (지표 화면·본부) — 홍보 효과를 잴 수 없으면 크게 알리지 않는다
- [ ] **방문 측정 동작 확인 (운영에서 1회)**: `?utm_source=test-launch` 를 붙여 운영 주소에 들어가 ① 그냥 보고 나가기 ② 핵심 행동까지 하기를 각각 해 본 뒤, 지표 화면에 **방문(landing)과 출처(src)·핵심 행동이 둘 다** 찍히는지 본다. 핵심 행동만 기록되고 "보고 나간 방문"이 0건이면 No-Go — 홍보 효과를 잴 수 없다(spec S6 `landing` 이벤트, 운영 통계 `../../build/references/ops-stats.md`)
- [ ] 좁은 화면(360~390px) 실측 캡처로 핵심 화면 확인 (design D4) — 버튼·짧은 글자 줄바꿈 없음
- [ ] (링크 공유·여럿이 고치는 서비스) build 체크리스트 "공유 링크" 절 통과 — 되돌리기·변경 기록·고치기·새로고침 없이 보이기
- [ ] 장애 대응 런북 있음 (operate O2): 롤백·점검 모드·공지 방법
- [ ] 최근 백업 존재, 복구 실습 완료 (operate O3)
- [ ] 비용 알림·한도 설정
- [ ] 문의 채널 동작 (operate O4)
- [ ] (앱) 스토어 심사 통과, 출시 방식(즉시/예약/단계적) 결정
- [ ] 처리방침·약관 링크 동작

## 권장
- [ ] 베타 사용자에게 출시 알림 예고
- [ ] 채널별 게시글·이미지·영상 준비
- [ ] 예상 질문 답변 (가격, 개인정보, 지원 기기, 로드맵)
- [ ] 출시 후 48시간 일정 비워 두기

## 출시일 운영
| 시점 | 할 일 |
|---|---|
| 게시 전 | 운영 스모크 테스트, 대시보드(에러·트래픽·비용) 열기 |
| 게시 | 주력 채널 1개 게시 → 베타 사용자·지인에게 알림(투표 요청이 아니라 소식 공유) |
| 첫 1~3시간 | 모든 댓글에 답변, 오류 실시간 확인. 치명 버그는 즉시 핫픽스 또는 롤백 |
| 하루 종일 | 트래픽·가입·오류율·외부 API 비용 1~2시간마다 확인 |
| 마감 | 수치 기록, 받은 피드백 정리, 다음 날 채널 준비 |

## 긴급 상황
- 서버 과부하 → 한도 강화·캐시·점검 모드, 상태 공지
- 비용 폭주 → 해당 기능 플래그 끄기
- 치명 버그 → 롤백 우선, 원인 분석은 나중에
- 절차 상세는 operate 의 `incident-runbook.md`
