# 랜딩 페이지·스토어 문구

## 랜딩 페이지 구조 (위에서 아래로)
1. **히어로**: 헤드라인(결과 중심, 10단어 안팎) + 서브헤드(누구를 위해, 어떻게) + 행동 버튼 1개 + 제품 화면
2. **문제 공감**: 대상 사용자가 겪는 상황 2~3개
3. **해결 방식**: 핵심 기능 3개 = 이점 중심 문장 + 화면
4. **증거**: 실제 사용자 후기, 사용 수치 (없으면 생략. 지어내지 않는다)
5. **가격** (있다면): 2~3개 요금제, 추천 표시
6. **FAQ**: 가격·데이터·해지·지원 기기
7. **마지막 행동 버튼**
8. 푸터: 처리방침·약관·연락처·(유료면) 사업자 정보

## 헤드라인 공식
- [결과] without [고통] — "엑셀 없이 5분 만에 끝나는 가계부"
- [대상]을 위한 [카테고리] — "1인 카페 사장님을 위한 재고 관리"
- 기능 나열("AI 기반 스마트 플랫폼")은 피한다.

## 스토어 문구
| 항목 | 요령 |
|---|---|
| 제목 | 앱 이름 + 핵심 키워드 (스토어별 글자 수 제한 확인) |
| 부제/짧은 설명 | 한 문장 가치 제안 |
| 스크린샷 | 첫 2~3장이 전부다. 각 장에 이점 한 줄 캡션 |
| 설명 | 첫 3줄에 핵심. 이후 기능 목록, 마지막에 문의처 |
| 키워드 | 경쟁 앱 제목·리뷰에서 사용자가 쓰는 단어 |

## 측정
- 버튼마다 이벤트, UTM 으로 채널별 유입 구분
- 문구 A/B 테스트는 방문자가 충분할 때만 (적으면 결과가 노이즈)
