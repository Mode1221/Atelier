# 유저 테스트

## 1. 사용성 테스트 (출시 전)
- **5명**이면 주요 사용성 문제 대부분이 드러난다 (Nielsen). 고치고 다시 5명.
- 대상 사용자와 비슷한 사람. 개발자 지인은 피한다.
- 원격(화면 공유)도 충분하다.

### 진행 스크립트
1. 안내: "제품을 테스트하는 거지 당신을 테스트하는 게 아닙니다. 생각나는 걸 소리 내어 말해 주세요."
2. 과제 3~5개 제시 — 목표만 주고 방법은 알려 주지 않는다.
   - 좋은 예: "다음 주 토요일 친구와 갈 코스를 만들어 저장해 보세요."
   - 나쁜 예: "'코스 만들기' 버튼을 누르세요."
3. 관찰: 멈칫함, 잘못 누름, 포기. 도와주지 않는다. "어떻게 하실 것 같아요?"로 되묻는다.
4. 마무리 질문: 가장 헷갈린 곳, 가장 좋았던 곳, 누구에게 추천하겠나.

### 기록 표
| 과제 | 성공/부분/실패 | 걸린 시간 | 막힌 지점 | 발언 |

### 심각도
- 치명: 과제 실패 → 출시 전 반드시 수정
- 높음: 성공했지만 오래 헤맴
- 낮음: 불만·취향

## 2. 설문
- **SUS** (System Usability Scale): 10문항 5점 척도, 68점이 평균 수준.
- 짧은 출시 후 설문:
  1. 이 제품을 무엇에 쓰고 있나요?
  2. 가장 유용한 점은?
  3. 가장 불편한 점 하나는?
  4. 이 제품이 없다면 대신 무엇을 쓰겠나요?

## 3. PMF 설문 (Sean Ellis test)
"이 제품을 더 이상 쓸 수 없다면 어떤 기분일까요?"
- 매우 실망 / 약간 실망 / 실망하지 않음 / 이제 안 씀
- **매우 실망 40% 이상**이 PMF 신호로 널리 쓰이는 기준. 실제 사용자 30명 이상일 때 의미가 있다.
- "매우 실망" 응답자의 공통점 = 진짜 타깃. 그들의 이유를 강화한다.

## 4. 베타 운영
- 앱: TestFlight / Play 비공개 테스트. 게임: Steam Playtest, itch.io 비공개 페이지, Discord.
- 피드백 채널 하나 (폼 또는 Discord 채널). 버그 신고 양식: 기기·재현 단계·기대 결과·실제 결과.
- 베타 사용자에게 변경 사항을 알려 준다 — "당신 의견으로 고쳤다"가 충성 사용자를 만든다.
