# Launch — 출시·테스트

목표: **알맞은 사람에게 닿게 하고**, 그들의 반응을 **다음 로드맵으로 바꾼다.**

## 입력
- `docs/idea.md` (대상 사용자, 고유 가치 제안, 채널, 핵심 지표)
- 배포 URL / 테스트 빌드

## 절차

### 1. 출시 전 유저 테스트
`references/user-testing.md` 를 따른다.
- 5명 사용성 테스트(과제 기반) → 치명 문제 수정 → 소규모 베타.
- AI 가 할 일: 테스트 과제·스크립트·설문 작성, 결과 정리.
- 사람이 할 일: 테스터 모집·진행.

### 2. 랜딩 페이지 · 스토어 등록 정보
`references/landing-copy.md` 구조로 만든다.
- 헤드라인 = 린 캔버스의 고유 가치 제안.
- 앱은 스토어 제목·부제·설명·스크린샷 문구, 게임은 스토어 페이지·트레일러 구성안.
- 분석 도구로 방문 → 가입/다운로드 전환을 측정한다.

### 3. 채널별 홍보
`references/launch-channels.md` 에서 대상 사용자가 있는 채널 3~5개를 고른다.
- 채널마다 **규칙과 문화에 맞춰 따로** 쓴다. 같은 글 복붙 금지.
- 광고가 아니라 **만든 이야기·배운 점·도움 요청** 형식이 반응이 좋다.
- 게시·답글은 사람이 한다. AI 는 초안과 예상 질문 답변을 준비한다.
- 출시 일정표를 만든다: D-14 ~ D+7.

### 4. 피드백 수집·분석
- 수집 경로를 하나로 모은다 (앱 내 피드백, 설문, 커뮤니티 댓글, 스토어 리뷰, 이메일).
- 분류: 버그 / 사용성 / 기능 요청 / 칭찬 / 이탈 이유.
- 빈도 × 심각도로 우선순위를 매긴다. 한 사람의 큰 목소리보다 **여러 사람의 같은 불편**을 우선한다.
- 결과를 PROJECT.md 로드맵에 다음 항목으로 넣는다.

### 5. 지표 점검 (출시 1·2·4주 후)
- 핵심 지표(린 캔버스 8번)와 퍼널: 방문 → 가입/설치 → 첫 가치 경험 → 재방문(D1·D7) → 유료.
- 가장 크게 빠지는 단계 하나를 다음 개선 목표로 정한다.
- PMF 설문(`user-testing.md`)은 사용자 30명 이상일 때.

## 산출물
- `docs/launch.md`: 테스트 결과, 채널 계획·일정표, 피드백 분류표, 지표 기록
- 랜딩 페이지 / 스토어 문구, 채널별 게시글 초안

## 완료 조건
- [ ] 사용성 테스트 5명 이상, 치명 문제 수정
- [ ] 랜딩/스토어 페이지 공개, 전환 측정 중
- [ ] 3개 이상 채널에 게시
- [ ] 첫 피드백 분류·우선순위화, PROJECT.md 반영

## 원칙
- 가짜 후기·조작된 수치·지인 동원 추천(업보트 품앗이)은 쓰지 않는다. 채널 규칙 위반이고 신뢰를 잃는다.
- 광고성 정보 발송(이메일·푸시)은 수신 동의가 있는 사람에게만 (guard 참고).
