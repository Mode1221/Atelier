# 업종별 기능·정책 패턴 (도메인 지식 없이 시작하기)

대표가 업종을 몰라도 빠지면 운영 중에 터지는 것을 미리 채우기 위한 표. idea I6(MVP 범위)·spec S1(스토리)·S2(정책)·S6(지표)에서 해당 업종 절만 읽는다.
- **필수 흐름**: 이것 없이는 서비스가 성립하지 않는다 → Must 후보.
- **꼭 정할 정책**: S2 표에 그대로 넣는다(빈칸이면 운영 중 분쟁).
- **지표**: S6 북극성·이벤트 후보.
- **흔한 실패**: idea I3 위험 가정 후보, launch 전 재확인.
- **규제 id**: `../../guard/scripts/rules-kr.mjs --yes <id>` 로 판정.
- **템플릿**: `../../build/templates/add.mjs <이름>`.

여러 업종이 섞이면(예: 예약 + 결제 + 후기) 해당 절을 모두 읽는다. 표에 없는 업종은 가장 가까운 절 + 경쟁 서비스 3개(idea I2)의 이용약관·도움말에서 정책을 뽑는다.

## 예약 (식당·미용·클래스·상담·공간 대여)
- 필수 흐름: 빈 시간 보기 → 예약 → 확인 알림 → 변경·취소 → 방문 전 알림 → (노쇼 처리)
- 꼭 정할 정책: 취소 가능 시한·수수료(예: 24시간 전까지 무료) · **노쇼** 처리(예약금·이용 제한) · 같은 시간 중복 예약 방지(동시 요청 — DB 고유 제약) · 운영자가 시간 막기(휴무·점심) · 시간대 기준(한국 시간 고정) · 대기 명단 여부
- 지표: 예약 완료율(보기→예약), 노쇼율, 재예약률, 운영자 응답 시간
- 흔한 실패: 공급자(가게)가 일정 갱신을 안 해서 빈 시간이 틀림 → 공급자 화면을 가장 쉽게 · 알림을 안 받아 노쇼 → 전날·2시간 전 알림
- 규제 id: pay(예약금) · ads_msg(알림에 광고 섞지 않기)
- 템플릿: pay · notify · admin

## 마켓플레이스·중고거래 (사람 ↔ 사람)
- 필수 흐름: 올리기(사진) → 검색·지도 → 대화 → 거래 약속 → 완료 표시 → 후기
- 꼭 정할 정책: 금지 품목(술·담배·의약품·위조품·동물·개인정보) · 사기 신고·차단 · 거래 방식(직거래만 / 안전결제) · 판매자 확인(본인 인증 범위) · 후기 조작 방지(거래 완료자만) · 탈퇴 시 거래 중인 건
- 지표: 등록 → 첫 대화까지 시간, 거래 완료율, 재방문 판매자 비율, 신고율
- 흔한 실패: 닭과 달걀(판매자 없으면 구매자 없음) → 한 동네·한 품목으로 좁혀 시작 · 대금을 직접 받음(전자금융 문제) → PG 지급대행
- 규제 id: market · ugc · loc · pay
- 템플릿: upload · search · map · realtime(대화) · admin

## 커뮤니티·게시판·SNS
- 필수 흐름: 가입 → 글·댓글 → 반응 → 알림 → 신고 → 운영자 처리
- 꼭 정할 정책: 금지 게시물 목록 · 신고 처리 기준·시간 · 제재 단계(경고 → 일시 정지 → 영구) · 삭제 글 보존 기간(분쟁 대비) · 실명/익명 · 미성년자 이용
- 지표: 주간 글쓴이 수(쓰는 사람 비율 1~10%), 첫 글까지 시간, 신고 처리 시간
- 흔한 실패: 첫 화면이 비어 있음 → 운영자가 첫 30개 글 · 악성 이용자 한 명이 분위기를 망침 → 신고·차단을 출시 전에
- 규제 id: ugc · kids · adult
- 템플릿: upload · search · notify · admin

## 구독 콘텐츠·멤버십 (뉴스레터·강의·자료실)
- 필수 흐름: 무료 맛보기 → 결제 → 바로 열람 → 갱신 알림 → 해지
- 꼭 정할 정책: 무료/유료 경계 · 해지 시 남은 기간 이용 · 환불(사용 시작 전 7일 등) · 공유 계정 제한 · 가격 인상 사전 고지
- 지표: 무료 → 유료 전환율, 월 해지율(churn), 사용자당 매출(ARPU)
- 흔한 실패: 해지가 어려움 → 분쟁·스토어 거절 · 새 콘텐츠 주기를 못 지킴 → 출시 전 4주 분량 미리
- 규제 id: pay · sub · edu
- 템플릿: pay(정기) · notify

## 교육·과외·스터디
- 필수 흐름: 과정 찾기 → 신청·결제 → 수업(영상·실시간) → 진도·과제 → 수료
- 꼭 정할 정책: 환불(진도율 기준) · 녹화·자료 재배포 금지 · 강사-수강생 직접 거래 금지 여부 · 미성년자 보호자 동의
- 지표: 완강률, 2번째 과정 구매율
- 규제 id: edu · kids · pay
- 템플릿: pay · upload · realtime

## 습관·건강·기록 (운동·식단·수면·가계부)
- 필수 흐름: 오늘 기록(10초 안에) → 쌓인 기록 보기 → 알림 → 주간 돌아보기
- 꼭 정할 정책: 기록 내보내기·삭제 · 민감정보 최소 수집 · "의학적 조언 아님" 문구 · 알림 시각 사용자 지정
- 지표: 7일·30일 유지율, 주당 기록 일수
- 흔한 실패: 기록이 귀찮아 3일 만에 이탈 → 한 번 누르기 기록·기본값 · 숫자만 쌓이고 의미 없음 → 주간 요약
- 규제 id: health · bio · finance(가계부는 보관·송금 없으면 대개 해당 없음)
- 템플릿: notify · ai(요약)

## 모임·이벤트·정산 (n빵·준비물·투표)
- 필수 흐름: 만들기 → 링크 공유 → 참여(가입 없이) → 결정·정산 → 끝
- 꼭 정할 정책: 링크 권한(보기/편집/관리) · 관리 링크 분실 시 · 데이터 보존 기간(끝난 모임 자동 삭제) · 실명 대신 별명
- 지표: 만들기 → 2명 이상 참여율, 참여자 → 다음 모임 만든 비율(바이럴)
- 흔한 실패: 링크 받은 사람이 뭔지 모름 → 첫 화면 한 줄 설명 · 송금 기능 욕심 → 송금 앱 링크로
- 규제 id: (대개 없음) · pay(후원)
- 템플릿: realtime(함께 편집) · notify

## 가게 1곳 주문·예약 (빵집·카페·공방 자체 앱)
- 필수 흐름: 메뉴 → 담기 → 픽업 시간 → 결제 → 주문 알림(가게) → 준비 완료 알림(손님)
- 꼭 정할 정책: 품절 처리 · 주문 마감 시각 · 취소 가능 시점(제조 시작 전) · 영수증·현금영수증
- 지표: 주문 완료율, 재주문율, 평균 주문 금액
- 흔한 실패: 가게가 알림을 못 봄 → 가게용 알림을 소리·카톡으로 · 메뉴 갱신이 어려움 → 운영자 화면 우선
- 규제 id: pay · food(직접 제조·판매면)
- 템플릿: pay · notify · admin

## 구인·구직·알바
- 필수 흐름: 공고 올리기 → 검색 → 지원 → 연락 → 결과
- 꼭 정할 정책: 공고 검수(최저임금 미달·허위·불법 업종 차단) · 개인정보(이력서) 열람 범위·보관 기간 · 연락처 공개 시점
- 지표: 공고당 지원 수, 지원 → 연락률
- 규제 id: job · ugc · kids(청소년 근로)
- 템플릿: search · notify · admin

## 여행·일정·장소 추천
- 필수 흐름: 목적지·날짜 → 추천·검색 → 일정 짜기(지도) → 공유 → 당일 보기
- 꼭 정할 정책: 장소 정보 출처·갱신 주기(폐업 정보) · 지도 API 무료 한도 · 사용자 위치 저장 안 함
- 지표: 일정 완성률, 공유율, 여행 후 재방문
- 흔한 실패: 장소 데이터가 낡음 → 출처 링크·제보 버튼 · 지도 호출 폭주 → 캐시
- 규제 id: loc · travel(상품 판매 시)
- 템플릿: map · search · ai(추천)

## AI 도구 (요약·작성·이미지·상담봇)
- 필수 흐름: 입력 → 결과(빠르게, 진행 표시) → 고치기·다시 → 저장·공유
- 꼭 정할 정책: 무료 사용 한도(사용자별·하루 전체 비용 상한) · AI 결과 고지 · 입력 저장 여부·학습 사용 여부 · 금지 입력(타인 개인정보·불법)
- 지표: 첫 결과까지 시간, 결과 재사용(복사·저장)률, 사용자당 AI 비용 vs 매출
- 흔한 실패: 비용이 매출보다 빠르게 늘어남 → 한도·싼 모델·캐시 먼저 · 결과 품질 들쭉날쭉 → 예시 입력 버튼
- 규제 id: ai · (상담이면) health · pro · finance
- 템플릿: ai · pay

## B2B 업무 도구 (팀용 SaaS)
- 필수 흐름: 팀 만들기 → 초대 → 핵심 작업 → 권한 → 내보내기 → 결제(좌석)
- 꼭 정할 정책: 역할(소유자·관리자·멤버) · 소유자 탈퇴 시 팀 데이터 · 데이터 내보내기·삭제 · 좌석 과금 방식 · 계약서·세금계산서
- 지표: 팀당 활성 인원, 초대 수락률, 유료 전환까지 기간
- 흔한 실패: 혼자 써 보고 끝남 → 초대를 첫 흐름에 · 기업 요구(SSO·보안 문서)에 끌려다님 → 작은 팀부터
- 규제 id: pay
- 템플릿: pay(정기) · admin · notify

## 캐주얼 게임
- 필수 흐름: 바로 시작(가입 없이) → 1분 안에 첫 재미 → 점수·랭킹 → 다시 하기 → 공유
- 꼭 정할 정책: 랭킹 부정행위(서버 검증) · 닉네임 욕설 필터 · 유료 아이템 환불·확률 공개
- 지표: 1일 유지율, 판당 플레이 수, 공유율
- 규제 id: game · lootbox · kids
- 템플릿: realtime(대전) · ads · iap (게임 설계는 `game-design.md`)
