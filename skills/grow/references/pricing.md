# 수익화·가격

## 과금 기준 (가치 지표)
사용자가 얻는 가치와 함께 늘어나는 단위로 과금한다: 프로젝트 수, 사용량, 좌석, 고급 기능.

## 무료 / 유료 경계
- 무료로 **핵심 가치를 경험**할 수 있어야 한다 (aha 는 무료)
- 유료는 더 많이·더 편하게·함께: 한도 확대, 고급 기능, 협업, 광고 제거
- 비용이 드는 기능(LLM·API)은 무료 한도를 둔다 (idea I5 공헌이익)

## 가격 정하기
- 경쟁·대안 가격(idea I2), 사용자가 지금 쓰는 돈·시간
- 요금제 2~3개, 연간 할인
- 처음엔 **조금 높게**: 올리기보다 내리기(할인)가 쉽다
- 가격 인터뷰: "이 가격이면 너무 싸서 의심된다 / 싸다 / 비싸다 / 너무 비싸서 안 산다" (Van Westendorp)

## 가격 변경
- 기존 유료 사용자는 기존 가격 유지 기간(grandfathering) 검토
- 인상은 미리 고지 (약관·스토어 정책 확인)

## 광고 (광고 모델이면)
- 핵심 흐름을 방해하지 않는 위치
- 보상형 광고(게임)는 사용자 선택
- 광고 SDK 수집 항목 → 처리방침·스토어 표시·동의(ATT 등) 반영 (guard)

## 수익 모델 고르기 (형태별 기본값)
| 서비스 | 기본 모델 | 구현 (Atelier 템플릿) | 먼저 확인 |
|---|---|---|---|
| 웹 도구·SaaS | 월 구독 + 무료 한도 | `build/templates/pay/` (정기결제) | 무료로 핵심 가치를 겪는가 |
| 가끔 쓰는 웹 도구 | 이용권(횟수·기간) | `pay/` (단건 `once`) | 한 번에 쓰는 가치가 분명한가 |
| 콘텐츠·정보 사이트 | 광고 | `build/templates/ads/` + 승인 체크리스트 | 월 페이지뷰 추정(ads-monetization 계산식) |
| 모바일 앱 (디지털 기능) | 인앱 구독 | `build/templates/iap/` (RevenueCat) | 스토어 수수료(15~30%) 반영 가격 |
| 게임 | 광고(보상형) + 광고 제거·아이템 | ads / iap | 확률형 아이템이면 확률 공개 의무(guard) |
| 기업 고객(B2B) | 월 구독 + 세금계산서 | `pay/` + 사업자 결제 | 일반과세자 필요 여부(tax-kr) |
| 후원형 | 토스 송금·카카오페이 링크·Buy Me a Coffee | 링크 버튼 (결제 연동 불필요) | 대가 없는 후원인지(세금은 소득) |

## 첫 매출까지 (출시 후 4주 계획)
1. **유료 가치 하나** — 무료 사용자 중 가장 자주 쓰는 사람이 더 원하는 것 1개(한도·기능·광고 제거). 의견·지표(R1)로 고른다.
2. **가격표 페이지** (`/pay/pricing.html`) + 결제 템플릿을 테스트 키로 붙여 끝까지 결제·환불해 본다.
3. **사람 할 일 병행**: 사업자등록 → 통신판매업 신고 → 결제사 가맹 신청(심사 1~2주). 그동안 테스트 키로 운영.
4. **첫 10명은 직접** — 베타 사용자·의견 남긴 사람에게 얼리버드(첫 3개월 할인)를 제안한다. 공지만으로 첫 결제가 나오는 경우는 드물다.
5. **숫자 보기**: 결제 전환율 = 결제한 사람 ÷ 주간 활성 사용자, 구독 유지율(해지·갱신 실패), 매출(본부 운영 지표 `revenue`). 2주 동안 0이면 가격이 아니라 **유료 가치**부터 다시 본다(인터뷰 5명: "무엇이 있으면 돈을 내겠어요?").
6. **해지 이유 묻기** — 해지 화면에 한 줄 선택지(비싸다/안 쓴다/기능 부족/기타). 고객지원 부서가 주간 정리.
