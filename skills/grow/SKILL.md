# Grow — 성장

목표: 감이 아니라 **지표와 피드백**으로 다음 할 일을 정하고, 작은 개선을 빠르게 반복한다.
끝나는 단계가 아니다. 보통 **2~4주 주기**로 돈다.

## 입력
- 분석 이벤트(spec S6), 문의·피드백 태그(operate O4), 비용(operate O5), 출시 회고(launch L7)

## 세부 단계

### R1. 지표 대시보드
`references/metrics.md`. 북극성 지표 1개 + 퍼널 + 리텐션 + 수익 + 비용을 한 화면에.

### R2. 퍼널·코호트 분석
- 퍼널에서 **가장 많이 빠지는 단계 하나**를 찾는다.
- 가입 주차별 코호트로 리텐션 곡선을 본다. 곡선이 **평평해지는가**(= 남는 사람이 있다)가 PMF 의 첫 신호.
- 남는 사용자와 떠나는 사용자의 첫 주 행동 차이를 찾는다.

### R3. 온보딩·리텐션 개선
`references/retention.md`. 활성화(aha moment)까지 시간 단축, 습관 트리거, 이탈 이유 인터뷰.

### R4. 수익화·가격
`references/pricing.md`. 가치 지표 기준 과금, 무료/유료 경계, 가격 실험.

### R5. 실험
`references/experiments.md`. 가설 → 지표 → 최소 표본 → 기간 → 결과 판단. 트래픽이 적으면 A/B 대신 전후 비교·인터뷰.

### R6. 로드맵 재정렬
- 후보: 피드백 태그 상위, 퍼널 최대 이탈 지점, 실험 결과, 기술 부채·운영 이슈.
- RICE 로 점수 → 상위 1~3개만 다음 주기에.
- 선택한 항목은 **기능 사이클**(pilot 5절)로 보낸다: spec → design → build → guard → 릴리스.
- idea I6 중단 기준을 다시 본다. 지표가 계속 기준 아래면 방향 전환(pivot)도 선택지다.

## 산출물
- `docs/growth.md`: 주기별 기록 — 지표 스냅숏, 발견, 실험, 결정
- PROJECT.md "기능 사이클" 표 갱신

## 주기 완료 조건
- [ ] 대시보드 스냅숏 기록
- [ ] 최대 이탈 지점 1개 특정
- [ ] 다음 주기 작업 1~3개 선정 (근거 = 지표 또는 피드백)
- [ ] 이전 주기 실험·변경의 결과 판단 기록

## 원칙
- 한 번에 하나씩 바꾼다. 여러 개를 동시에 바꾸면 무엇이 효과였는지 모른다.
- 허영 지표(누적 가입자·페이지뷰)보다 행동 지표(활성화율·리텐션·유료 전환).
- 다크 패턴(해지 방해, 숨은 결제, 가짜 긴급성) 금지 — 법·스토어 정책 위반 소지.
