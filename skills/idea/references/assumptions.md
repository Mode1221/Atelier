# 가정 검증 — 가장 위험한 가정부터 (I4)

아이디어는 "사실이라고 믿는 것들"의 묶음이다. 만들기 전에 **틀리면 망하는 가정**부터 싸게 확인한다.

## 1. 가정 목록 (15분)
문제·해결·사업을 문장으로 쪼갠다. 세 종류로 나눈다.
| 종류 | 질문 | 예 (챙김표) |
|---|---|---|
| 원하나 (Desirability) | 이 사람들이 정말 이 불편을 겪고, 바꾸고 싶어 하나 | 총무는 준비물 나누기를 귀찮아한다 · **친구들이 링크를 눌러 이름을 적는다** |
| 되나 (Feasibility) | 1인·무료 스택으로 만들고 운영할 수 있나 | 동시 맡기 충돌 없이 무료 등급 안에서 |
| 남나 (Viability) | 돈·시간이 남는 구조인가 | 제휴 수수료가 생길 만큼 목록이 쌓인다 |

## 2. 위험 순서 (5분)
각 가정에 **중요도**(틀리면 끝인가) × **근거 부족**(지금 증거가 없나)을 1~3점으로 매겨 곱한다. 높은 순 3개가 "가장 위험한 가정".
보통 1등은 "원하나" 쪽이다 — 만들 수는 있는데 아무도 안 쓰는 경우가 가장 흔하다.

## 3. 실험 설계 (가정마다 한 줄)
| 가정 | 가장 싼 실험 | 성공 기준 (숫자, 미리 정함) | 기한 | 결과 |
|---|---|---|---|---|
| 친구들이 링크를 눌러 참여한다 | 공개 베타 첫 20개 목록 | 목록의 50% 이상이 참여자 2명 이상 | 출시 +2주 | |
| 총무가 다음 여행에도 쓴다 | 같은 기기에서 두 번째 목록 | 20% 이상 | 출시 +6주 | |
- 실험은 싼 순서: 검색·커뮤니티 글 → 인터뷰 5명 → 가짜 문(랜딩에 버튼만 두고 클릭 수) → 대기 명단 → 최소 기능 공개 베타.
- **성공 기준은 결과를 보기 전에** 적는다. 보고 나서 정하면 무엇이든 성공처럼 보인다.
- 기준을 못 넘으면: I6 중단 기준·grow R6 로 (방향 바꾸기·접기도 성공한 결정이다).

## 4. 연결
- 성공 기준의 숫자는 spec S6 이벤트로 **잴 수 있어야** 한다 (못 재면 이벤트를 추가).
- 결과는 `docs/idea.md` 표의 "결과" 칸과 PROJECT.md 결정 기록에.
