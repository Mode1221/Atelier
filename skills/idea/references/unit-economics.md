# 사업성 계산

숫자는 추정이어도 된다. **추정이라고 표시하고**, 무엇이 가장 불확실한지 적는다.

## 1. 비용
| 항목 | 월 고정비 | 사용자당 변동비 | 비고 |
|---|---|---|---|
| 호스팅·DB | | | 무료 한도 넘는 시점 |
| 외부 API (지도·LLM·SMS 등) | | | 호출당 단가 × 사용자당 호출 수 |
| 도메인·이메일 | | | |
| 개발자 계정 | | | Apple 연 회비, Google 1회 등록비 (최신 금액 확인) |
| 도구 구독 | | | |
| 결제 수수료 | | 매출의 % | 스토어 수수료(소규모 사업자 우대 요율 확인), PG 수수료 |
| 세금 | | | 부가세·소득세는 전문가 확인 |

## 2. 수익
| 모델 | 계산 |
|---|---|
| 구독 | 유료 사용자 수 × 월 가격 × (1 − 수수료율) |
| 일회성 | 월 판매 수 × 가격 × (1 − 수수료율) |
| 광고 | 월 노출 수 ÷ 1000 × eCPM (장르·국가별 편차 큼) |
| 인앱 결제 | 활성 사용자 × 결제 전환율 × 결제자당 평균 매출 |

## 3. 핵심 숫자
- **손익분기 유료 사용자 수** = 월 고정비 ÷ (사용자당 월 매출 − 사용자당 월 변동비)
- **필요 전체 사용자 수** = 손익분기 유료 사용자 ÷ 유료 전환율
  - 전환율 가정은 보수적으로 (프리미엄 모델에서 흔히 한 자릿수 %)
- **공헌이익률** = (사용자당 매출 − 변동비) ÷ 사용자당 매출. 음수면 쓸수록 손해 → 가격·한도 재설계

## 4. 위험 신호
- 사용자당 변동비가 큰데 무료 한도가 없다 (LLM·지도 API 에서 흔함) → 사용량 한도 설계를 spec S2 에 넣는다
- 광고 수익에 의존하는데 대상 사용자가 적다
- 손익분기 사용자 수가 경쟁 서비스 전체 사용자보다 많다

## 출력
위 표 + 핵심 숫자 3개 + "가장 불확실한 가정" 1~2개
