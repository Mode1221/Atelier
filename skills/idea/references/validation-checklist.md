# 수요 검증 방법

싸고 빠른 순서. 코드를 쓰기 전에 1~2개는 해 본다.

| 방법 | 비용 | 기간 | 신호 |
|---|---|---|---|
| 커뮤니티 불만 조사 | 0 | 1일 | 같은 불만 글이 반복되는가 |
| 문제 인터뷰 5~10명 | 0 | 1~2주 | 지금 돈·시간을 쓰고 있는가 |
| 대기자 명단 랜딩 페이지 | 0~소액 | 1~2주 | 방문 대비 등록률 (참고: 5~10% 이상이면 긍정) |
| 가짜 문(Fake door) 버튼 | 0 | 1주 | 없는 기능 버튼 클릭률 |
| 사전 판매 / 크라우드펀딩 | 0 | 2~4주 | 실제 결제. 가장 강한 신호 |
| 컨시어지 MVP | 시간 | 2~4주 | 수작업으로 서비스해도 계속 쓰는가 |
| 게임: 프로토타입 공개 (itch.io 등) | 0 | 1~2주 | 플레이 시간, 재플레이, 댓글 |
| 게임: Steam 페이지 위시리스트 | 스토어 등록비 | 수주~수개월 | 위시리스트 수 |

등록률 기준은 업계 경험치다. 절대 기준이 아니므로 비슷한 제품과 비교해서 본다.

## Mom Test 인터뷰 원칙
(Rob Fitzpatrick, *The Mom Test*) — 엄마도 거짓말을 못 하게 묻는 법.
1. **내 아이디어를 말하지 않는다.** 상대의 삶과 문제를 묻는다.
2. **미래·가정이 아니라 과거의 구체적 행동**을 묻는다.
3. **말보다 행동**(돈·시간을 이미 썼는가)을 믿는다.

### 좋은 질문
- "그 문제를 마지막으로 겪은 게 언제예요? 그때 어떻게 하셨어요?"
- "지금은 어떻게 해결하고 있어요? 그 방법의 불편한 점은요?"
- "그걸 해결하려고 돈이나 시간을 써 보셨어요?"
- "이 문제에 대해 더 얘기해 볼 만한 사람이 있을까요?"

### 나쁜 질문
- "이런 앱 있으면 쓰실 거예요?" (예의상 "네")
- "얼마면 사실 거예요?" (가정)
- "이 아이디어 어때요?" (칭찬 유도)

## 결과 판단
- 강한 신호: 결제·선주문, 인터뷰 중 "언제 나와요?", 자발적인 지인 소개
- 약한 신호: "좋네요", "재밌겠다", 좋아요 수
- 약한 신호만 있으면 **문제나 대상을 다시 좁힌다.**
