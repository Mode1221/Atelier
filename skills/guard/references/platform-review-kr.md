# 소셜 로그인 심사·검수 (카카오·네이버·구글)

소셜 로그인은 **코드가 끝나도 심사가 끝나기 전에는 일반 사용자가 못 쓴다.** 개발 중 상태에서는 등록한 계정만 로그인된다.
심사는 며칠~몇 주 걸리고 반려되면 다시 기다린다 → **출시일에서 거꾸로 2주 전**에 제출한다.

원칙: **제출은 사람, 제출물은 AI.** 제출 버튼·본인 인증·사업자 정보는 사람이 하고, 캡처·수집 사유 문구·URL 목록은 AI 가 만든다.
기준은 자주 바뀐다. 아래는 **2026-10-01 확인** 기준의 흐름이다. 실행할 때마다 공식 문서에서 최신 조건을 다시 확인하고, 다르면 이 파일을 고친다.

## 공통 제출물 (AI 가 미리 만든다 → `docs/review/`)
| 제출물 | 만드는 법 |
|---|---|
| 가입 동선 캡처 | usertest 계획에 `shot` 단계를 넣어 자동 저장(`shots/review/*.png`): ① 로그인 버튼이 보이는 첫 화면 ② 약관·처리방침 동의 화면 ③ 가입 완료(로그인된) 화면 ④ 탈퇴 메뉴. 소셜 사업자 화면(카카오 동의 창 등)은 자동화가 막히므로 사람이 휴대폰으로 1장씩 찍어 같은 폴더에 |
| 수집 항목·사유 표 | guard G3 수집 항목 표에서 **소셜 로그인으로 받는 항목만** 뽑아 "항목 / 왜 필요한가(화면에서 어디에 쓰는지) / 필수·선택". 쓰지 않는 항목은 요청하지 않는다(반려 1순위) |
| URL 목록 | 서비스 주소, 처리방침 주소, 약관 주소, 리다이렉트(콜백) URI — **운영 주소 기준**, 개발 주소와 따로 |
| 테스트 계정 안내 | 심사자가 로그인 뒤 무엇을 보면 되는지 3줄 |

## 카카오 로그인
공식: [카카오 로그인 이해하기](https://developers.kakao.com/docs/latest/ko/kakaologin/common) · [사전 설정](https://developers.kakao.com/docs/latest/ko/kakaologin/prerequisite) · [앱 설정(비즈 앱)](https://developers.kakao.com/docs/latest/ko/app-setting/app) · [데브톡](https://devtalk.kakao.com)
1. 앱 만들기 → 플랫폼에 **사이트 도메인** 등록(운영 주소, 바꾸면 다시) → 카카오 로그인 활성화 → **리다이렉트 URI** 등록(운영·개발 각각, 끝 `/` 까지 정확히).
2. **동의항목**: 닉네임·프로필 사진은 기본으로 쓸 수 있다. **이메일을 받으려면 비즈 앱**이어야 하고, 필수 동의로 받으려면 별도 신청이 필요할 수 있다.
   - 사업자가 없으면 **개인 개발자 비즈 앱**(앱 소유자 본인 인증)으로 전환한다. 개인 개발자 비즈 앱은 쓸 수 있는 권한이 사업자 비즈 앱보다 좁다 — 필요한 항목이 되는지 공식 문서에서 먼저 확인.
   - 이메일이 꼭 필요하지 않으면 **카카오 회원번호로만 계정을 만든다**(심사 부담·개인정보 둘 다 줄어든다).
3. 출시 전 테스트: 앱 **팀 멤버**로 초대한 카카오계정만 로그인된다(초대는 그 사람의 카카오계정 이메일로).
4. 동의항목 사용 신청·검수(필요한 항목일 때): 서비스 URL, 처리방침, 가입 동선 캡처, 항목별 수집 사유를 낸다.
- 흔한 반려: 사유가 "회원 관리" 처럼 막연함 · 서비스 화면에서 그 항목을 쓰는 곳이 안 보임 · 처리방침에 항목이 없음 · 사이트에 접속이 안 되거나 준비 중 화면 · 도메인과 리다이렉트 URI 불일치.

## 네이버 로그인
공식: [네이버 로그인 개발가이드](https://developers.naver.com/docs/login/devguide/devguide.md) · [내 애플리케이션](https://developers.naver.com/apps)
1. 애플리케이션 등록 → 사용 API "네이버 로그인" → 받을 정보(필수/선택) → **서비스 URL** 과 **Callback URL** 등록(운영 주소, 둘의 도메인이 맞아야 한다).
2. 등록 직후는 **"개발 중"** — 멤버 관리에 등록한 아이디만 로그인된다("개발 중 상태에서는 등록된 아이디만" 경고).
3. **검수 요청**: 로그인 버튼 → 네이버 동의 화면 → 약관 동의 → 가입 완료까지 **전 과정 캡처**(하나의 파일로 묶기)와 받는 정보별 사용 이유. 검수용 테스트 아이디가 필요하면 멤버로 등록.
- 흔한 반려: 로그인 흐름 캡처가 끊김(버튼·동의 화면 빠짐) · 받는 정보를 화면에서 안 씀 · 서비스 URL 과 실제 주소가 다름 · 네이버 로그인 버튼 디자인 가이드 위반.

## 구글 로그인
공식: [OAuth 동의 화면(브랜딩)](https://support.google.com/cloud/answer/10311615) · [앱 대상(테스트/프로덕션)](https://support.google.com/cloud/answer/15549945) · [검증 제출](https://support.google.com/cloud/answer/13461325) · [확인되지 않은 앱](https://support.google.com/cloud/answer/7454865)
1. 외부(External) 사용자 유형 → **테스트** 상태에서는 등록한 테스트 사용자(최대 100명)만, 동의가 7일 뒤 만료된다.
2. **프로덕션으로 게시**한다. 기본 범위(이메일·프로필·openid)만 쓰면 보통 바로 쓸 수 있지만, 앱 이름·로고를 동의 화면에 보이게 하면 **브랜드 확인**(영업일 며칠)이 필요하다.
3. 민감·제한 범위(드라이브·지메일 등)를 쓰면 **범위 검증**(영업일 10일 안팎 이상, 시연 영상 요구)이 필요하다 → 꼭 필요한지부터 다시 본다.
- 준비: 홈페이지·처리방침 주소가 같은 도메인, 도메인 소유 확인(Search Console), 앱 이름이 다른 브랜드와 헷갈리지 않게.

## Apple 로그인
iOS 앱에서 다른 소셜 로그인을 제공하면 Apple 로그인(또는 같은 수준의 대안)이 요구될 수 있다 → `store-review-checklist.md`.

## 주소가 바뀌면 (도메인 이전)
카카오 사이트 도메인·리다이렉트 URI, 네이버 서비스·Callback URL, 구글 승인된 리디렉션 URI·도메인을 **지우지 말고 새 주소를 추가**한 뒤, 새 주소로 로그인 확인 후 옛 것을 정리한다(`../../build/references/domain.md` 4절).

## "사람 할 일"에 적는 형식
```
- [ ] 카카오 로그인 검수 제출 (약 20분) — developers.kakao.com → 내 애플리케이션 → 동의항목. 제출물: docs/review/kakao/ (캡처 4장, 수집 사유 표, URL 목록). 결과 메일이 오면 대화창에 "카카오 검수 결과" 라고 알려 주세요.
```
결과(승인일·반려 사유)는 `docs/guard.md` 심사 표에 남긴다. 반려되면 사유를 이 파일의 "흔한 반려"에 일반 항목으로 추가한다.
