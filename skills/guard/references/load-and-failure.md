# 부하·장애 테스트

## 1. 부하 테스트
- 도구: k6, Artillery, Locust (스테이징 환경에서. 운영에 하지 않는다)
- 시나리오: 실제 사용 흐름 (랜딩 → 가입 → 핵심 행동)
- 목표 부하: spec S5 동시 사용자 × 2. 모르면 "출시 게시글 하나로 1시간에 수천 명 방문"을 가정
- 볼 것: 오류율, p95 응답 시간, DB 연결 수, 메모리, 외부 API 호출 수·비용
- 병목 흔한 곳: DB 인덱스 없음, 연결 풀 부족, 서버리스 콜드 스타트, 외부 API 속도 제한, 이미지 원본 전송

## 2. 장애 주입
하나씩 꺼 보고 사용자에게 무엇이 보이는지 확인한다.
| 끄는 것 | 기대 동작 |
|---|---|
| 외부 API 키 제거 / 응답 지연 | 폴백 + 안내, 전체 장애 아님 |
| DB 연결 끊김 | 오류 화면 + 재시도, 데이터 손실 없음 |
| 이메일 발송 실패 | 재시도 큐, 사용자에게 재발송 버튼 |
| 결제 웹훅 지연 | "처리 중" 표시, 나중에 반영 |
| 느린 네트워크 (클라이언트) | 로딩 표시, 타임아웃 후 재시도 |

## 3. 비용 폭주 테스트
- 한 사용자가 스크립트로 반복 호출 → 한도에서 막히는가
- 한도가 없으면 최악의 경우 하루 비용을 계산해 둔다
