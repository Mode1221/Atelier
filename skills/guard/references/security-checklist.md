# 보안 체크리스트

OWASP Top 10 / OWASP MASVS(모바일) 의 1인 개발 핵심만 추렸다.

## 비밀값
- [ ] API 키·DB 비밀번호·서명 키가 코드·커밋 이력·로그에 없다
- [ ] 클라이언트 번들(웹 JS, 앱 바이너리)에 **서버 전용 키**가 없다. 클라이언트에 들어가는 키는 공개된다고 가정한다
- [ ] 공개 키(예: Supabase anon key)를 쓴다면 서버 측 권한(RLS 등)으로 보호된다
- [ ] 외부 API 키에 사용량 한도·도메인/앱 제한을 걸었다

## 인증·권한
- [ ] 인증은 검증된 서비스/라이브러리를 쓴다 (직접 구현 금지)
- [ ] 모든 API 가 **서버에서** 권한을 확인한다. "내 것만 볼 수 있다"를 ID 바꿔 요청해서 확인 (IDOR)
- [ ] DB 행 단위 권한(RLS)을 켰다 (Supabase/Firebase 규칙 포함)
- [ ] 관리자 기능은 별도 권한 + 추측 불가능한 경로만으로 보호하지 않는다
- [ ] 비밀번호를 직접 저장한다면 bcrypt/argon2 해시
- [ ] 세션·토큰 만료, 로그아웃 시 무효화
- [ ] 로그인·가입·비밀번호 재설정에 속도 제한
- [ ] 속도 제한의 클라이언트 IP 는 **신뢰하는 프록시가 덮어쓰는 헤더**만 읽는다. `X-Forwarded-For` 를 그대로 믿으면 헤더 위조로 한도를 우회한다 (회귀 테스트로 남긴다)

## 입력·출력
- [ ] SQL 은 파라미터 바인딩/ORM (문자열 이어붙이기 금지)
- [ ] 사용자 입력을 HTML 로 렌더링할 때 이스케이프 (XSS)
- [ ] 파일 업로드: 형식·크기 제한, 실행 불가 위치에 저장
- [ ] 서버가 사용자가 준 URL 로 요청한다면 내부 주소 차단 (SSRF)
- [ ] LLM 을 쓰면: 프롬프트 주입 가정, 모델 출력을 그대로 실행·쿼리하지 않음, 사용자별 호출 한도

## 전송·저장
- [ ] 전 구간 HTTPS
- [ ] 쿠키 `HttpOnly`, `Secure`, `SameSite`
- [ ] CORS 는 필요한 출처만
- [ ] 보안 헤더: CSP, `X-Content-Type-Options`, `Referrer-Policy`
- [ ] 민감정보(주민번호·결제정보·건강정보)는 가능하면 **저장하지 않는다**. 결제는 PG사에 맡긴다
- [ ] 백업 암호화, 백업 접근 권한 최소화

## 모바일 추가
- [ ] 토큰은 Keychain / Keystore(또는 SecureStore)에 저장
- [ ] 디버그 로그·테스트 엔드포인트가 운영 빌드에 없음
- [ ] 딥링크 파라미터 검증

## 게임 추가
- [ ] 재화·순위·보상은 서버가 판정 (클라이언트 값 신뢰 금지)
- [ ] 결제 영수증 서버 검증

## 운영
- [ ] 의존성 취약점 스캔 CI 에 포함 (Dependabot 등)
- [ ] 오류 응답에 스택트레이스·내부 정보 노출 없음
- [ ] 비용 폭주 방지: 클라우드·API 요금 알림과 한도
- [ ] 사고 대응 메모: 키 폐기 방법, 사용자 공지 방법, 연락처
