# Guard — 보안·법률

목표: 출시 후 **사고(유출·해킹·다운)** 와 **분쟁(법·스토어 거절·라이선스)** 가능성을 출시 전에 줄인다.
5단계 외에도 **배포·출시 직전마다**(기능 사이클 포함) 변경분 기준으로 다시 돈다.

> ⚠️ 이 스킬의 법률 관련 산출물은 **참고용 초안**이다. 법적 효력을 보장하지 않는다.
> 모든 법률 산출물 맨 위에 이 안내를 붙이고, 사업 규모가 커지거나 민감정보를 다루면 전문가 검토를 권한다.
> 법·정책은 자주 바뀐다. 조항·기준을 인용할 때는 공식 출처(법제처, 개인정보보호위원회, 스토어 정책 페이지)에서 최신본을 확인한다.

## 세부 단계

### G1. 보안 점검
1. `/security-review` 를 실행한다.
2. `references/security-checklist.md` 를 항목별로 확인하고 결과표를 남긴다.
2-1. 비밀값 자동 검사: `scripts/secret-scan.mjs` (키·토큰·개인키·JWT 모양, 올라간 `.env`) — build 품질 게이트에 포함돼 매 push 마다 돈다.
3. 의존성 취약점 스캔: `npm audit` / `pip-audit` / 스택별 도구. CI 에 자동 스캔(Dependabot 등) 추가.
4. 비밀값 스캔: 저장소 전체 이력. 노출됐으면 **키 폐기·재발급**이 먼저다(이력 삭제만으로는 부족).
5. 권한 우회 시도: 다른 사용자 ID·관리자 경로·한도 우회를 직접 요청해 본다.

### G2. 부하·장애 테스트
`references/load-and-failure.md` 를 따른다. 출시일 트래픽(홍보 게시 직후 몰림)을 버티는지, 외부 서비스가 죽으면 어떻게 되는지 확인한다.

### G3. 개인정보·수집 항목
1. 코드·DB 스키마(spec S3 🔒 필드)·분석 도구·SDK 에서 **수집 항목**을 목록화한다 (IP·기기 ID·쿠키·광고 ID 등 자동 수집 포함).
2. 항목별 목적·보유 기간·제3자 제공·처리 위탁·국외 이전 여부를 표로 만든다.
3. `references/privacy-checklist-kr.md` 로 법 의무를 확인한다. **생성형 AI 기능이 있으면** 같은 파일 "인공지능 기본법" 절로 고지 위치(기능 화면·약관)와 결과물 표시 방법을 정하고, 화면 문구를 build 작업으로 넘긴다.
4. 최소 수집: 목적에 필요 없는 항목은 수집을 없애는 쪽을 먼저 제안한다.

### G4. 처리방침·약관
`references/legal-docs-outline.md` 로 개인정보처리방침·이용약관(해당 시 위치정보 약관·환불 정책·커뮤니티 정책) 초안을 만든다.
- G3 표의 **실제 항목**으로 채운다. 템플릿 문구를 사실 확인 없이 넣지 않는다.
- 게시 위치: 앱·웹 내부(설정·푸터), 스토어 등록 정보.

### G5. 라이선스
`references/license-checklist.md` 로 오픈소스·폰트·이미지·음원·AI 생성물·게임 에셋을 점검하고 고지 파일을 만든다.

### G6. 스토어·플랫폼 심사 대비
`references/store-review-checklist.md` 로 거절 사유를 미리 확인한다. 심사용 데모 계정·심사 메모를 준비한다.
**광고 수익형(애드센스·애드핏·AdMob)이면** 광고 네트워크 승인도 심사다: `../grow/references/ads-monetization.md` "승인 전 체크리스트"를 항목 그대로 확인해 `docs/guard.md` 에 표로 남기고(자체 도메인·ads.txt 포함), 신청은 "사람 할 일"로. 웹 검색 요약으로 대신하지 않는다.
**소셜 로그인(카카오·네이버·구글)이 있으면** `references/platform-review-kr.md` 로 검수 제출물(가입 동선 캡처 — usertest `shot` 단계, 수집 사유 표, URL 목록)을 `docs/review/<서비스>/` 에 만들고, 제출은 서비스별로 "사람 할 일"에 올린다. 심사에 며칠~몇 주 걸리므로 **출시 2주 전**에 낸다.

### G7. 사업·업종 신고 (사람이 할 일)
같은 파일의 "사업·업종 신고" 표를 사용자 상황에 맞춰 체크리스트로 전달한다. 신고 자체는 사람이 한다.
**idea I5 에 수익 경로가 있으면** `references/tax-kr.md` 로 `docs/guard.md` "세금" 표(사업자등록 시점·과세 유형·신고 달력·수익 경로별 차이·경비 증빙·감면 확인)를 만들고, 할 일은 "사람 할 일"에, 신고 기한은 checkup 분기 점검에 넣는다. 금액·기준은 적지 않고 공식 링크와 확인일만. 무료 서비스면 N/A.

### G8. 운영 계정 보안 (사람이 켠다, AI 가 목록을 만든다)
서비스가 해킹당하는 흔한 길은 코드보다 **운영 계정**(Cloudflare·GitHub·도메인·스토어·결제·이메일)이다. 1인 운영자는 계정 하나를 잃으면 서비스 전체를 잃는다.
1. 서비스 지도(B14) 계정 목록의 계정마다 **2단계 인증**을 켠다(문자보다 인증 앱·패스키). 복구 코드는 비밀번호 관리자나 종이에.
2. 운영에 쓰는 이메일 자체도 2단계 인증 (다른 계정의 비밀번호 재설정 통로라서).
3. API 토큰은 필요한 권한만(예: Cloudflare 토큰은 해당 계정의 Workers·D1 만), 만료일이 있으면 만료 목록에.
4. 결제 수단 등록 계정은 요금 알림을 켠다.
5. 결과를 서비스 지도 "계정" 표의 "2단계 인증" 칸에 ✅ 로. 켜는 일은 "사람 할 일"(계정마다 5분).
