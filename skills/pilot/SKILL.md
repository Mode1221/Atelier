# Pilot — 오케스트레이터

목표: 아이디어에서 **실제로 운영 가능한 서비스**까지, 빠뜨리는 단계 없이 한 걸음씩 안내한다.

## 1. 상태 확인
- 프로젝트 루트의 `PROJECT.md` 를 읽는다.
- 없으면 **인터뷰**(2절) 후 `templates/PROJECT.md` 로 만든다.
- 있으면 "현재 단계"와 첫 번째 미완료 세부 단계를 찾아 안내한다.

## 2. 인터뷰 (신규일 때만, 한 번에 하나씩)
사용자가 "알아서 해", "전부 채워" 처럼 맡기면 **자동 모드**로 진행한다.
- 질문 대신 합리적인 가정으로 채우고, 문서마다 맨 위에 "가정 기반" 표시, 가정은 `(가정)` 으로 표시한다.
- 핵심 가정(대상·문제·과금)은 PROJECT.md "결정 기록"에 남긴다.
- 사람만 할 수 있는 일은 멈추지 말고 "사람 할 일" 절(7절)에 모은 뒤 다음 준비 작업을 계속한다.
- "사람 할 일"로 보이는 것도 먼저 자동화할 길을 찾는다: 사용성 테스트 → `usertest`(AI 대리), 베타 모집·피드백 → `beta`(공개 링크 + 자동 수집), 홍보 게시 → `share`(버튼 한 번).
- **배포 없이 되는 검증은 배포를 기다리지 않는다.** build 게이트 전에 로컬 서버(`wrangler dev --local`, 빈 로컬 DB)로 `atelier:usertest` 를 돌리고 치명·높음을 고친다. "사람 대기"·"배포 후"로 미루는 것은 실제 계정·운영 주소가 꼭 필요한 일뿐이다.

1. 무엇을 만드나? (웹 / 모바일 앱 / 게임 / 데스크톱 / 기타) 한 문장 설명
2. 누구를 위한 것인가? 어떤 문제를 푸나?
3. 돈을 받나? (무료 / 광고 / 구독 / 일회성 / 인앱 결제 / 미정)
4. 사용자 계정이 필요한가? 사용자 데이터(개인정보·업로드)를 저장하나?
5. 개발 경험 수준과 선호 스택
6. 목표 일정, 주당 투입 시간
7. 쓸 수 있는 예산 — 기본은 **무료 우선(운영비 0원)**. 답이 없으면 무료 우선으로 둔다

## 3. 프로필로 로드맵 맞추기
답을 **프로필**로 PROJECT.md 에 적고, 해당 없는 세부 단계는 삭제하지 말고 `N/A (이유)` 로 표시한다.
| 프로필 | 영향 |
|---|---|
| 형태 = 게임 | spec 에 코어 루프·밸런스 추가, launch 에 플레이테스트, guard 에 등급분류·확률 공개 |
| 형태 = 모바일 앱 | build 에 스토어 빌드·서명, guard 에 스토어 심사, operate 에 강제 업데이트 |
| 과금 있음 | build 결제, guard 전자상거래·환불, grow 수익화 |
| 계정 있음 | build 인증·탈퇴, guard 개인정보 전체 |
| 경험 적음 | 세부 단계마다 개념 설명을 붙이고, 관리형 서비스를 우선 추천 |
| 예산 = 무료 우선 (기본) | 스택은 `build/references/free-tier.md` 의 무료 기본값, 유료가 불가피한 항목(스토어 등록비 등)은 인터뷰 직후 **한 번에 미리** 안내 |

## 4. 단계와 게이트
| # | 단계 | 스킬 | 게이트 (다음으로 가는 조건) |
|---|---|---|---|
| 1 | 아이디어 검증 | idea | MVP 범위·중단 기준 확정 |
| 2 | 기획 | spec | 사용자 스토리·데이터 모델·아키텍처·비기능 요구 확정 |
| 3 | 디자인 | design | 핵심 화면 시안 확정, 접근성 기준 통과 |
| 4 | 구현 | build (+ 로컬 usertest) | 운영 준비 체크리스트(`../build/references/production-readiness.md`) 필수 항목 통과, **로컬 서버로 돌린 AI 대리 사용성 테스트 치명·높음 0** |
| 5 | 보안·법률 | guard | 치명 이슈 0, 법률 문서 게시, 출시 준비 점검 통과 |
| 6 | 출시 | launch (+ usertest · beta · share) | 공개 출시 완료, 출시 회고 작성 |
| 7 | 운영 | operate | 모니터링·장애 대응·백업·CS 체계 가동 (출시 직후 병행 시작) |
| 8 | 성장 | grow | 지속 단계 — 끝이 없다. 주기적으로 반복 |

- 게이트 조건이 안 채워지면 다음 단계로 넘어가지 않는다. 남은 세부 단계를 보여 준다.
- 게이트 판정은 세 가지: **통과 / 보류(사람 대기) / 미통과**. 보류는 코드·문서로 할 수 있는 일은 다 끝났고 계정·결제·실제 사용자 같은 사람 일만 남은 상태다.
  보류일 때는 다음 단계의 **준비 작업은 해도 되지만 완료 체크는 하지 않는다.** 보류 항목은 launch L5 Go/No-Go 에서 다시 확인한다.
- build 게이트 판정 전에 `atelier:usertest` 를 로컬 서버로 실행한다(자동 모드면 묻지 않고). 배포·계정이 없어도 되므로 이 항목은 보류 사유가 될 수 없다.
- **operate 는 launch 와 동시에 시작한다**(출시 당일 장애 대응이 가능해야 하므로 O1~O3 는 출시 전에 끝낸다).
- guard 는 5단계 외에도 **배포·출시 직전마다** 다시 돈다.
- 출시 후에는 **정기 점검 보고서**(`docs/ops/reports/`, `ops-report`·`ops-alert` 이슈)도 다음 할 일의 입력이다. "다음에 뭐 해?"라고 하면 최근 보고서의 FAIL·TODO 부터 확인한다. 자동화 설치는 `/atelier:checkup setup`.

## 5. 출시 후: 기능 사이클
출시 뒤 새 기능·큰 변경은 같은 흐름을 **작게** 반복한다.
`grow(무엇을 할지) → spec(스토리·수용 기준) → design(필요 시) → build → guard(변경분) → 릴리스(operate O7) → grow(지표 확인)`
PROJECT.md "기능 사이클" 표에 한 줄씩 기록한다.

## 5-1. AI 회사 모드 (본부 만들기)
**서비스 주소가 처음 생기면**(launch L2 공개 베타 시작, 늦어도 6단계 게이트 전) 사용자에게 한 줄로 확인받고 `atelier:company setup` 을 실행한다.
예: "이제 AI 부서들이 매일 일하게 본부를 만들까요? (켜 둔 부서는 실행마다 Claude 사용량이 들어요)" → "응"이면 진행.
- 본부는 **그 사용자의 claude.ai 계정에** 만들어진다(이 세션에서 게시 = 본인 소유·비공개). 다른 사람의 본부 링크를 쓰지 않는다.
- 이미 본부가 있으면 새로 만들지 않고 이 서비스를 같은 본부에 추가한다(company A-0).
- 클라우드 세션이 아니면(company A 의 확인) 클라우드 세션에서 여는 방법을 안내하고 PROJECT.md "사람 할 일"에 적는다.
이후 사람은 본부에서 결재·체크만 한다.

## 6. 진행 방식
- 세부 단계 하나씩 진행한다. 시작할 때 "이번 세부 단계 목표, AI 가 할 일, 사용자가 할 일"을 먼저 말한다.
- AI 가 할 수 있는 일은 사용자 승인 후 직접 한다.
- 사람만 할 수 있는 일(계정 생성, 결제, 신고, 스토어 제출, 법률 최종 판단, 실제 인터뷰)은 체크리스트로 안내한다.
- 단계 게이트에서 `reviewer` 에이전트로 검토한 뒤 완료 처리한다.
- 사용자가 단계를 건너뛰려 하면 생기는 위험을 한 줄로 말하고, 그래도 원하면 `건너뜀 (이유)` 로 기록한다.

## 6-1. 비용 안내
`../build/references/free-tier.md` 3절 규칙을 모든 단계에 적용한다.
- 인터뷰 직후: 프로필로 예상되는 **피할 수 없는 비용**(예: iOS 앱이면 Apple 연 $99)을 금액·시점·대안과 함께 먼저 알린다.
- 돈이 드는 선택(유료 서비스, 카드 등록, 유료 API)은 실행 전에 무료 대안과 비교해 사용자 결정을 받는다.
- PROJECT.md "비용" 절을 최신으로 유지한다: 지금 월 비용, 예정된 비용, 유료로 넘어가는 조건.

## 7. 사람 할 일
- 여러 단계에 흩어진 사람 몫(인터뷰, 계정 생성, 결제, 신고, 운영자 정보 입력, 테스터 모집)을 PROJECT.md **"사람 할 일"** 절에 한곳으로 모은다.
- 항목마다 어느 세부 단계를 막고 있는지 적는다. 사용자에게는 이 목록을 한 번에 전달한다.
- 첫 배포(Cloudflare 스택)는 한 줄만 적는다: `Cloudflare 가입(무료) 후 터미널에서 npm run deploy:first` — DB·마이그레이션·설정은 스크립트가 한다(build B1). 토큰·Secrets 설정을 사람 할 일로 적지 않는다.

## 8. 기록
- 세부 단계가 끝날 때마다 PROJECT.md 체크박스, "현재 단계", "결정 기록"을 갱신한다.
- 체크박스는 세부 단계 ID 로 **정확히 일치**하는 줄만 바꾼다 (예: `B1` 을 바꿀 때 `B12` 가 같이 바뀌지 않게).
- 해당 없음은 `N/A (이유)`, 사람 대기는 `— 사람 대기 (무엇)` 을 줄 끝에 붙인다.
- 세션 기억에 의존하지 않는다. 다음 세션은 PROJECT.md 만 보고 이어간다.
