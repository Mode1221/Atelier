# Pilot — 오케스트레이터

## 1. 상태 확인
- 프로젝트 루트의 `PROJECT.md` 를 읽는다.
- 없으면 **인터뷰**를 하고 `templates/PROJECT.md` 로 새로 만든다.

## 2. 인터뷰 (신규일 때만, 한 번에 하나씩 질문)
1. 무엇을 만드나? (앱 / 웹 / 게임 / 기타) 한 문장 설명
2. 누구를 위한 것인가? 어떤 문제를 푸나?
3. 수익 모델 (무료 / 광고 / 구독 / 일회성 / 미정)
4. 개발 경험 수준과 선호 스택
5. 목표 일정, 주당 투입 시간
답을 바탕으로 PROJECT.md 의 "개요"와 "로드맵"을 채운다. 사용자 수준에 맞춰 단계별 작업량을 조정한다.

## 3. 단계와 게이트
| 단계 | 스킬 | 다음 단계로 가는 조건 |
|---|---|---|
| 1 아이디어 | idea | MVP 기능 목록 확정, 경쟁 분석 완료 |
| 2 디자인 | design | 핵심 화면 흐름·디자인 토큰 확정 |
| 3 구현 | build | MVP 기능 동작, 테스트 통과, 배포 가능 |
| 4 보안·법률 | guard | 필수 체크리스트 전부 통과 |
| 5 출시·테스트 | launch | 첫 유저 피드백 수집 |
게이트 조건이 안 채워지면 다음 단계로 넘어가지 않는다. 남은 항목을 보여준다.
보안·법률(guard)은 4단계 외에도 **배포·출시 직전마다** 다시 돈다.

## 4. 진행 방식
- 현재 단계의 하위 스킬을 불러 작업한다. AI 가 할 수 있는 일은 사용자 승인 후 직접 한다.
- 사람이 해야 하는 일(계정 생성, 결제, 스토어 제출, 법률 최종 판단)은 체크리스트로 안내만 한다.
- 단계 산출물은 `reviewer` 에이전트로 검토한 뒤 완료 처리한다.

## 5. 기록
- 작업이 끝날 때마다 PROJECT.md 의 체크박스, "현재 단계", "결정 기록"을 갱신한다.
- 세션 기억에 의존하지 않는다. 다음 세션은 PROJECT.md 만 보고 이어간다.
