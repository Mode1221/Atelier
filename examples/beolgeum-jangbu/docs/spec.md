# 기획 — 벌금장부

> Atelier `spec` 스킬로 작성.

## 권한 모델 (계정 없음)
- 모임을 만들면 두 개의 링크가 생긴다.
  - **관리 링크** `/g/<groupId>?k=<adminKey>` — 편집 가능. adminKey 는 128비트 이상 무작위, DB 에는 **해시만** 저장.
  - **보기 링크** `/g/<groupId>` — 읽기 전용. 멤버에게 공유.
- 관리 링크를 잃어버리면 복구 불가 (MVP). 생성 직후 "복사·즐겨찾기" 안내를 강하게 보여 준다.

## S1. 스토리·수용 기준

### F1. 모임 만들기 (Must)
운영자로서 모임 이름과 벌금 규칙을 정해 모임을 만들고 싶다. 매번 계산하지 않기 위해.
1. Given 첫 화면 / When 이름 "알고리즘 스터디", 지각 1000·결석 3000·과제 미제출 2000 을 입력하고 만들기 / Then 관리 화면으로 이동하고 관리 링크·보기 링크가 보인다
2. (실패) Given 이름이 비어 있음 / When 만들기 / Then "모임 이름을 입력해 주세요" 가 보이고 입력값이 유지된다
3. (경계) Given 금액에 음수나 1,000,000 초과 / When 만들기 / Then "0~1,000,000원 사이로 입력해 주세요"

### F2. 멤버 관리 (Must)
운영자로서 멤버를 추가·삭제하고 싶다.
1. Given 관리 화면 / When "민수" 추가 / Then 멤버 목록에 민수가 보인다
2. (실패) Given 같은 이름 "민수" 존재 / When 다시 추가 / Then "이미 있는 이름이에요"
3. (경계) Given 멤버 30명 / When 추가 / Then "멤버는 30명까지예요"
4. Given 기록이 있는 멤버 / When 삭제 / Then 확인 후 **숨김 처리**(기록·합계 보존, 목록에서 "나간 멤버"로)

### F3. 회차 출결 기록 (Must)
운영자로서 모임 날마다 멤버별 상태를 체크하면 벌금이 자동으로 계산되길 원한다.
1. Given 멤버 3명 / When 새 회차(오늘 날짜) 만들고 민수=지각, 지영=결석+과제 미제출 저장 / Then 민수 1000, 지영 5000 이 회차 합계에 보인다
2. Given 저장된 회차 / When 민수를 출석으로 수정 / Then 민수 0, 누적 합계도 갱신
3. (실패) Given 네트워크 끊김 / When 저장 / Then 체크 상태가 유지되고 "저장하지 못했어요. 다시 시도" 버튼
4. (경계) Given 같은 날짜 회차 존재 / When 같은 날짜로 생성 / Then 허용(하루 2회 모임 가능), 목록에 "(2)" 표시

### F4. 정산 요약·납부 처리 (Must)
운영자로서 멤버별 누적 벌금·납부액·미납액을 한눈에 보고 납부를 기록하고 싶다.
1. Given 민수 누적 4000 / When 3000 납부 기록 / Then 미납 1000
2. (실패) Given 미납 1000 / When 5000 납부 입력 / Then 허용하되 "초과 납부 4000" 표시 (선불 가능)
3. 보기 링크에서도 요약이 보이고 편집 버튼은 없다

### F5. 링크 공유 (Must)
운영자로서 링크만 공유하면 멤버가 가입 없이 볼 수 있길 원한다.
1. Given 보기 링크 / When 멤버가 연다 / Then 요약·회차 기록을 볼 수 있다
2. (실패) Given 보기 링크 / When 편집 API 를 직접 호출 / Then 403
3. (실패) Given 틀린 관리 키 / When 편집 / Then 403, 키 시도 속도 제한
4. Given 존재하지 않는 모임 ID / Then 404 화면 "모임을 찾을 수 없어요"

### F6. 정산 요약 복사 (Should)
1. When "카톡용 복사" / Then "[알고리즘 스터디] 9월 벌금\n민수 1,000원 미납 …" 텍스트가 클립보드에

## S2. 기능 정책
| 항목 | 모임 | 멤버 | 회차·출결 | 납부 |
|---|---|---|---|---|
| 보기 | 보기 링크·관리 링크 | 동일 | 동일 | 동일 |
| 편집 | 관리 링크만 | 관리 링크만 | 관리 링크만 | 관리 링크만 |
| 상태 | 활성 → 삭제됨(즉시 비공개, 30일 후 영구 삭제) | 활성 → 숨김 | 저장됨 (수정 가능) | 기록됨 (삭제 가능) |
| 예외 | 삭제된 모임 링크 → 404 | 숨긴 멤버 이름 재사용 가능 | 동시 수정: 마지막 저장 우선 + `updated_at` 충돌 시 안내 | 중복 제출 방지(버튼 비활성) |
| 한도 | IP 당 모임 생성 시간당 10개 | 모임당 30명 | 모임당 회차 500개 | 금액 0~1,000,000 |
| 보존 | 삭제 요청 시 30일 후 영구 삭제. 90일간 조회 없는 모임은 안내 없이 보존(MVP), 정책 재검토 | — | — | — |

규칙 변경 시: 기존 회차 금액은 **기록 당시 규칙으로 고정**(회차에 금액 스냅숏 저장). 분쟁 방지.

## S5. 비기능 요구
| 항목 | 목표 |
|---|---|
| 응답 시간 | 주요 화면·API p95 500ms (로컬 측정 기준) |
| 가용성 | 월 99.5% |

| 복구 목표 | 손실 최대 24시간, 복구 2시간 |
| 월 비용 상한 | 1만 원 |
| 지원 환경 | 최신 Chrome·Safari(iOS 16+)·삼성 인터넷, 모바일 360px~ |
| 보안 수준 | 개인정보: 멤버 이름(별명 권장)만. 결제 정보 없음 |

## S6. 분석 이벤트
| 이벤트 | 언제 | 속성 | 지표 |
|---|---|---|---|
| `group_created` | 모임 생성 | 규칙 개수 | 획득 |
| `member_added` | 멤버 추가 | 멤버 수 | 활성화 준비 |
| `session_recorded` | 회차 저장 | 멤버 수, 회차 번호 | **활성화(첫 회차) / 북극성(주간 기록 모임 수)** |
| `payment_recorded` | 납부 기록 | — | 정산 사용 |
| `view_link_opened` | 보기 링크 열림 | — | 공유·바이럴 |
| `summary_copied` | 카톡용 복사 | — | 공유 |
| `request_failed` | API 오류 | 코드 | 품질 |
MVP 는 서버 로그 기반 집계(외부 분석 SDK 없음 → 쿠키 동의 불필요). 이름 등 개인정보는 이벤트에 넣지 않는다.
