# Atelier 실전 테스트 기록

샘플 프로젝트(벌금장부)를 Atelier 절차대로 진행하며 발견한 플러그인 개선점.

| # | 단계 | 발견 | 개선안 |
|---|---|---|---|
| 1 | pilot | 사용자가 "알아서 다 채워"라고 하면 인터뷰 절차가 없다 | **자동 모드**: AI 가 합리적 가정으로 채우고 모든 가정을 `(가정)` 표시, 결정 기록에 남김 |
| 2 | idea | 첫 아이디어(일정 조율)가 포화 시장이었는데, 포화 시 무엇을 할지 기준이 없다 | I2 에 "직접 경쟁 3개 이상이 같은 차별점을 갖고 있으면 피벗/틈새 재정의" 판단 규칙 |
| 3 | idea | I4(인터뷰)는 사람만 가능 → 게이트가 막히는지 불명확 | 게이트에 "검증 미실시 시 `미검증` 표시 + 출시 전 병행 과제로 이월" 허용 규칙 명시 |
| 4 | spec | 계정 없는 서비스의 권한 모델(링크 키)이 템플릿·체크리스트에 없다 — 정책 표가 "본인/관리자" 전제 | S2 에 "계정 없는 권한(비밀 링크·토큰)" 유형과 위험(유출·분실·재발급) 추가 |
| 5 | spec | 규칙이 바뀔 때 과거 기록을 어떻게 할지(스냅숏) 같은 "시간에 따른 데이터 변화" 질문이 없다 | S2 정책 표에 "설정 변경 시 과거 데이터 처리" 행 추가 |
| 6 | design | 접근성 체크리스트 덕에 입력 테두리 대비 미달(1.36:1)을 발견·수정 — **잘 작동** | 유지. 토큰 예시(`design-tokens.md`)에 `border-strong` 을 기본으로 넣기 |
| 7 | design | 시안을 사람에게 보여 주는 단계(D4 확인, D5 테스트)가 자동 모드에서 막힘 | 자동 모드: 스크린숏으로 AI 자체 검토 + "사람 확인 대기" 표시 후 진행 허용 |
| 8 | design | 브랜드 에셋 생성 방법(도구)이 없다 — Playwright 스크린숏으로 해결 | `brand-assets.md` 에 "HTML → 스크린숏" 생성법 추가 |
| 9 | build | 운영 준비 체크리스트가 "필수"인데 계정이 필요한 항목(에러 모니터링·호스팅·비용 알림)이 있어 자동 모드에서 게이트가 영원히 막힌다 | 게이트 판정에 **"코드 측 통과 / 사람 대기"** 상태 추가, 사람 대기 항목은 launch L5 Go/No-Go 로 이월 |
| 10 | build | 계정 없는 서비스에서 B3·B6 이 "인증·알림" 전제로 쓰여 있다 | B3 을 "신원·권한"으로 일반화 (계정 / 비밀 링크 / 기기 토큰) |
| 11 | build | E2E 가 vitest 에 잡혀 실패 — 스택 템플릿에 테스트 러너 경로 분리 안내가 없다 | `testing-strategy.md` 에 "단위·E2E 러너 경로 분리" 한 줄 |
| 12 | build | 컨테이너 빌드가 샌드박스 프록시 인증서로 실패 — 환경 문제지만 원인 찾는 데 시간 소모 | `ci-deploy.md` 에 "사내/샌드박스 프록시에선 CA 주입 빌드 변형 사용, 저장소엔 넣지 않음" 메모 |
| 13 | build | 롤백 실습·부하 측정 스크립트를 스킬이 요구했기에 실제로 해 봄 — **잘 작동** | 유지. `bench.js` 같은 측정 스크립트 템플릿을 스킬에 포함 |
| 14 | guard | 보안 체크리스트로 **X-Forwarded-For 위조로 속도 제한 우회** 취약점 발견·수정 — **잘 작동**. 다만 체크리스트에 이 항목이 명시돼 있진 않았다 | `security-checklist.md` 에 "클라이언트 IP 는 신뢰 프록시 헤더만" 항목 추가 |
| 15 | guard | 개인정보 체크리스트 덕에 해외 리전 호스팅 = **국외 이전 공개** 필요를 잡음 — **잘 작동** | 유지 |
| 16 | guard | 계정 없는 서비스에서 "정보주체 권리 행사"를 누가 어떻게 하는지(멤버는 링크가 없음) 가이드가 없다 | privacy 체크리스트에 "제3자(운영자)가 입력한 타인 정보" 유형 추가 |
| 17 | operate/checkup | 백업이 서버 볼륨에 있으면 GitHub Actions 의 `BACKUP_CHECK_CMD` 로는 확인할 수 없다 | 앱에 `/health?backup=1`(백업 나이) 패턴을 권장하고 `HEALTH_URLS` 로 검사 — checkup setup 에 안내 추가 |
| 18 | operate | 백업을 같은 볼륨에 두는 1인 구성이 흔한데, 오프사이트 필요성이 체크리스트 한 줄뿐 | O3 게이트에 "오프사이트 사본" 명시 |
| 19 | launch | 사람 대기 항목이 여러 단계(I4·D5·B9·B12·O1…)에 흩어져 한눈에 안 보인다 | PROJECT.md 템플릿에 **"사람 할 일" 절**을 두고 pilot 이 모아 관리 |
| 20 | launch | Go/No-Go 가 "사람 대기" 때문에 No-Go 로 끝남 — 자동 모드 테스트의 자연스러운 종착점 | 정상. 사람 할 일 목록을 사용자에게 한 번에 전달하는 것으로 마무리 |
| 21 | reviewer | 실제 파일을 확인해 **PROJECT.md 체크 상태와 docs 불일치(B12·B13 잘못 체크)** 를 잡음, 게이트를 "보류"로 판정 — **잘 작동** | 유지. 체크박스를 코드로 일괄 바꾸면 접두어 충돌(B1→B12) 위험 — pilot 에 "세부 단계 ID 는 정확히 일치로 갱신" 규칙 |
| 22 | reviewer | 권한 없이 E2E·audit 실행 불가로 "미확인" 처리 — 정직하게 보고함 | 에이전트 tools 에 테스트 명령 실행 허용 안내를 README 에 |
| 23 | pilot | 게이트 보류 상태에서도 다음 단계 문서 작업(launch·operate)을 진행함 — 자동 모드에선 합리적이지만 규칙 위반 | 게이트 보류 시 "사람 대기로 인한 보류는 다음 단계 준비 작업 허용, 완료 체크는 금지" 규칙 명시 |
| 24 | hook | 진행률이 "사람 할 일" 체크박스까지 세서 71개로 표시 | status.sh 는 `## 로드맵` 절 안의 체크박스만 센다 |
